Context Grammar — Stage 3

Dials

信頼とは、一枚の許可画面のことではありません。ひとつのダイヤルはAIが「何を知ってよいか」を制御し、もうひとつのダイヤルはAIが「何を行ってよいか」を制御します。

01 Disclosure は情報アクセス。人ごと、ドメインごとに設定される。
02 Autonomy は行動権限。実績によって段階的に獲得される。
03 Autonomy は、それを支える Disclosure を超えられない。

Quick overview

このページは、2つのプロダクト上の問いとして読む。

01

AIは何を知ってよいか

Disclosure は Full、Summary、Existence、Hidden などの段階を持つ。単純なオン/オフではない。

02

AIは何をしてよいか

Autonomy は Suggest、Confirm、Notify、Auto と進む。各段階で人間とAIの契約が変わる。

03

順序は正しいか

Disclosure が先に来る。理解を許されていないドメインでAIが行動することはできない。

04

誰との関係か

同じホームAIでも、舞、Kiran、葵、蒼太、Leo と各ドメインごとに Dial ペアが必要になる。

Restaurant model

信頼は、常連になるように育つ。

初めて行くレストランでは、慎重に注文する。何度か良い体験をすると、店員は好みを覚える。ずっと後になれば、「おまかせで」と言っても安心できる。

その進展には2つの動きが同時に必要だ。自分について少しずつ開示すること。そして、相手が選んでもよい権限を少しずつ獲得すること。片方だけでは信頼にならない。

Disclosure と Autonomy は、その2つの動きである。 Context Grammar は、AIとの関係が偶然ではなく意図的に育つように、名前、段階、ルールを与える。

The distinction

窓を開けることと、ハンドルを渡すことは別の設計だ。

Disclosure Dial

AIはどれだけ知っているか

健康、家計、家族、場所、予定、好みなどへの情報アクセス。ドメインごと、人ごとに深さが変わる。

Autonomy Dial

AIはどれだけ動けるか

提案だけか、実行前に確認するか、実行後に通知するか、信頼された範囲で静かに動くかを決める。

Disclosure Dial

Disclosure には Protect と Connect の2軸がある。

Protect

Human → AI

AIに何を見せるか。Full、Summary、Existence、Hidden。医療AIには Full、趣味AIには Hidden という設定ができる。

Connect

AI → Human

AIが他者に何を伝えてよいか。Push、Digest、Available、Off。葵の音楽をAIが知ることと、Kiranに話すことは別である。

Sync

AI ↔ AI / external

他システムに何を共有できるか。医療ポータルには Full、親には Summary、学校には Hidden という制御ができる。

Level Protect: AIが知る Connect: AIが共有する 例
Full / Push 詳細まで見える。 新しい情報をすぐに出せる。 医療AIが投薬履歴を完全に見る。娘の作品投稿を家族に即通知する。
Summary / Digest 集約やラベルだけが見える。 定期的なまとめとして出す。 Fitness AI は「やや運動不足」だけを見る。ダンス動画は週次ハイライトにする。
Existence / Available 存在は知るが中身は知らない。 聞かれたときだけ利用できる。 Travel AI は食事制限があることだけ知る。父のKindleは要求時だけ見られる。
Hidden / Off ドメイン自体が見えない。 そのドメインを共有しない。 趣味AIには健康データを見せない。私的なプレイリストは共有しない。
Share Disclosure V2: 知っていることと話すことは別

葵は家族AIに音楽の好みを知らせる。しかし、蒼太には詳しく話してよく、舞には曖昧に、Kiranには話さない。Intake Disclosure はAIが何を知るかを制御し、Share Disclosure は誰に何を言ってよいかを制御する。V1 schema は disclosure.share_with を予約し、V2 で強制する。

Logical dependency

Disclosure が先に来なければならない。

多くのAIプロダクトは、どこまで自動化するかから始める。Context Grammar は1つ手前から始める。開示していないものは委任できない。

ナッツアレルギーを伝える前に「おまかせ」と言うのは危険だ。残高や上限を知らない金融AIに実行権限を渡すのも同じ設計ミスである。

逆は成立する。Full Disclosure で低い Autonomy は整合的だ。健康トラッカーが全てを見ていても、提案だけに留められる。Disclosure が Autonomy の上限を決める。

Invalid

Low Disclosure × High Autonomy

AIが十分な文脈なしに行動している。これはリスクが高いだけでなく、論理的に成立していない。

Valid path

Disclosure を開き、その後 Autonomy を上げる

十分な Disclosure があるドメインだけが委任を受けられる。Disclosure がないドメインは Suggest に留まる。

Autonomy Dial

4段階。連続スライダーではない。

Stage 01

Suggest

AIは選択肢を出す。人間が決め、実行する。新しいドメインは必ずここから始まる。

Stage 02

Confirm

AIが候補を1つに絞り、実行前に確認する。ワンタップまたは音声で進む。

Stage 03

Notify

AIが先に動き、後から報告する。人間は取り消し、監査、次回ルール変更ができる。

Stage 04

Auto

限定された routine の中でAIが静かに動く。ログと例外処理は残る。

Three forces

Autonomy Dial はユーザーだけが動かすものではない。

「自動化レベルは自分で決める」という前提は不十分だ。実際の Autonomy は、3つの力の合成で決まる。

Force 01

Service default

Netflix autoplay、Amazon 1-Click、Spotify auto-advance など、プロダクト側が高い Autonomy で出荷する。

Force 02

AI adjustment

成功実績、確信度、失敗履歴に基づいて、システムが昇格や降格を行う。

Force 03

User override

「毎回聞かないで」「これは必ず確認して」という、人間の直接介入。

Concrete walkthrough

舞の火曜日の朝。

「蒼太のサッカーシューズ、小さくなってる。あと葵の部費、8,500円、今日締め切り。」

AIは先に Disclosure を読む

蒼太の靴サイズは家族AIに Full。家計は舞とKiranに Full。葵の学校詳細は Summary で、親はカテゴリだけを見る。

Autonomy はドメインごとに違う

1万円未満の子どもの必需品は Auto。定期支払いは Notify。初回の申し込みは Confirm。

3つの行動、3つの段階

蒼太の靴は静かに注文。葵の部費は送金後に通知。ピアノ教室の体験予約は、舞の確認を待つ。

UIは契約を反映する

routine は消え、支払いはレシートになり、初回予約は確認になる。画面は Dial ペアから生成される。

葵の Disclosure も同時に働く

葵自身の設定により、親には部費があることは見えるが詳細は見えない。同じ取引に2つの privacy layer がある。

Multi-Brain context

Dial ペアは、人ごと・ドメインごとに存在する。

山城家は1つのホームAIを共有している。しかし、共通の Autonomy level や Disclosure setting は存在しない。人 x ドメインごとに関係契約がある。

Coordinator Brain は、その Dial ペアを読んでから、どの Agent をどのモードで動かすかを決める。Agent は自分で権限を得ない。

Person / domain Disclosure Autonomy Coordinator reading
舞 / 家計 Full Notify 定期支払いを行い、後で報告できる。
蒼太 / 買い物 Full Auto 上限内の必需品を再注文できる。
葵 / 学校 Summary Suggest カテゴリだけを見せ、詳細は出さない。
Kiran / 仕事 Existence Suggest 中身を出さずに衝突を避けられる。

Q&A

よくある質問。

Disclosure はプライバシー設定と同じか？

違う。 多くのプライバシー設定は二値だ。Disclosure は段階を持ち、ドメインと人でスコープされ、AIが他者に何を言えるかも含む。

Auto になると人間は関与しないのか？

関与は残る。 Auto は限定された routine の中で毎回の割り込みをなくすだけだ。ログ、取り消し、例外、降格は残る。

Disclosure は後で閉じられるか？

閉じられる。 Dial を閉じると新しい情報の流れが止まる。Brain が既に学習したものを消すには別途 forget 操作が必要になる。

Tokens と Brain とはどうつながるか？

Situation Signals は観測された状況（Now Layer）を読み取り、Relationship Dials（Autonomy と Disclosure）は関係性の境界線を定義します。Context Brain は記憶と権限を保持し、Trust Design はその記憶へのアクセス範囲やそれに続くアクションの許容度を制御します。

信頼のコントロールがないメモリは、監視になる。
