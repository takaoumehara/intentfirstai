Context Grammar — Always-On Layer

Brain

AIの記憶を、ただの履歴ではなく構造として扱う。Context Brainは、変わらない素性、積み重なる学習、今この瞬間の状態を分けて読み、行動へつなげるための記憶アーキテクチャです。

01 すべてのBrainはIdentity・Learning・Nowの3層を持つ。
02 家族や組織の記憶は、ひとつに混ぜず分散させる。
03 CoordinatorとAgentが、記憶を実際の行動へ変える。

Definition

記憶には、更新速度の違う層がある。

Context Brainは、AIの記憶を「何者か」「何を学んだか」「今何が起きているか」に分ける設計です。

名前、アレルギー、家族構成のように変わりにくい情報。繰り返しから学ぶ好みや習慣。そして、今いる場所、相手、時間、緊急度のようにすぐ消える状態。これらを同じメモリに混ぜると、AIは何を固定し、何を学習し、何を一時的な状況として扱うべきかを判断できません。

Context Brainは、記憶を3つのLayerに分け、さらに家庭・個人・領域・イベントごとに複数のBrainとして分散させます。そこにCoordinatorとAgentが接続されることで、記憶は単なる保存先ではなく、次の行動を選ぶための材料になります。

Overview

まず、この4つだけ掴めばいい。

事実、制約、学習、現在状態をLayerごとに持つ。Brain自体は買い物も通知もしない。

02

Identity、Learning、Now。どのBrainにも同じ記憶の解剖学がある。

03

Coordinatorが読む

複数のBrainを横断し、どのAgentを動かすか、どこまで任せるかを決める。

Voice、Shopping、NotificationのようなAgentが、権限の範囲で実行し、学びを書き戻す。

Restaurant model

あなたを覚えているレストラン。

行きつけのレストランに入ると、良いスタッフはあなたを一つの情報として覚えているわけではありません。名前、アレルギー、いつもの席のように変わりにくい情報があります。

金曜日はビールを頼みやすい、疲れている日は軽い料理を好む、魚にはレモンを添える、といった繰り返しから学んだ傾向もあります。

さらに今夜は、上司と来ている。スーツを着ている。少し緊張している。会話を邪魔されたくなさそうだ。この「今」の読み取りがあるから、同じ常連でもサービスは変わります。

Context Brainが言いたいのは、この違いです。 記憶には更新速度の違う層があり、その層を分けないと、AIは人間らしい判断ができません。

Three layers

すべてのBrainは3つのLayerを持つ。

Identity Layer

そのBrainの素性。名前、制約、権限、境界、変わりにくい事実。レストランなら、予約名、アレルギー、いつもの席にあたる。

制御: この層の厚みはDisclosure Dialで変わる。Fullなら詳しい素性まで見せ、Hiddenなら名前だけ、あるいは存在自体を隠す。人ごと、領域ごとに開き方を変えられる。

Learning Layer

繰り返しから学んだ傾向。好み、習慣、失敗、修正。誤って学ぶこともあるため、AutonomyやTrustと接続して制御する。

修正: サーモンを3回注文したからといって、本人の好物とは限らない。来客用だった可能性もある。誤学習が続く場合はAutonomyを下げ、AIが勝手に決めず、より多く確認する。

Now Layer

今この瞬間の状態。場所、相手、時間、緊急度、空気感。状況シグナルと関係性ダイヤルが流れ込み、記憶を判断に変える場所。

ライブ入力: Physical State、Cognitive Load、Social Exposure、Priority Weight、Form Factor、Feasibility、Autonomy Dial、Disclosure Dial。

Right now

記憶は原材料だ。今と交差して初めて、判断になる。

Before

Identity + Learning

「卵アレルギー」「金曜は疲れている」「魚にはレモンを添える」。大事な記憶ではあるが、これだけではAIは動けない。

After

Identity + Learning + Now

「火曜18:30」「冷蔵庫にパスタとブロッコリー」「夕食まで25分」「妻がキッチンにいる」。Now Layerが入った瞬間、AIは提案、確認、自動実行のどれが適切かを選べる。

Action

Agent

実際に動く役割。聞く、探す、買う、通知する、記録する。

Orchestration

Coordinator

必要なBrainを読み、ルールを照合し、どのAgentに渡すかを決める。

1つのBrainは複数のAgentから読まれます。1つのAgentも複数のBrainを読めます。重要なのは、BrainとAgentを一対一で固定しないことです。

レストランに例えるなら、Brainは予約台帳と常連記録、Agentはシェフやウェイター、Coordinatorはフロアマネージャーです。良いサービスは、記憶、判断、行動が分かれていながら連携している状態です。

1つのAI、4つのルールセット

同じCoordinator、同じHousehold Brainを使いながらも、各個人のPerson Brainは異なるAutonomy Dial（自律性ダイヤル）設定とSubstitution Mode（代替モード）を保持します。1つのAIが、それぞれの条件に合わせて4人を同時にサポートします。

1つのBrain、4つの並行状態

CoordinatorはそれぞれのPerson Brainを独立して読み取ります。ルールが衝突した場合（母親は特定のヨーグルトを望んでいるが店舗で売り切れている場合など）でも、誰の好みを優先すべきかを判断できます。

Disposable Brain

目的のために生まれ、目的が終われば消える。

すべての記憶を永続させる必要はありません。京都旅行、引越し、台風対応、プロダクト発売、受験のように、期間限定の目的にはEvent Brainを作れます。

Event Brainは、Home Brainから必要なIdentityとLearningを引き継いで生まれます。目的の期間中だけNow Layerを持ち、終わったら価値ある学びだけをHome Brainへ戻して消えます。

Scale

個人、家族、企業まで同じ構造で伸びる。

Context Brainは、家族用の特殊な構造ではありません。個人ならSelf Brain、家族ならHousehold Brain、企業ならOrg Brainが土台になります。Domain Brainは、家庭ではFinanceやHealth、企業ではLegal、HR、Marketing、EngineeringのようなFunction Brainに変わります。

不変なのは、Brainが3つのLayerを持ち、Coordinatorが複数のBrainを横断し、Agentが行動するという構造です。変わるのはBrainの数と、Coordinatorの階層だけです。

Trust Designは、この記憶と行動に対して、どこまで見せるか、どこまで任せるかを制御します。

Q&A

よくあるご質問への回答

Brain（記憶）、Agent（行動）、Coordinator（調整役）— 5つの家庭用Brain — 3つのレイヤー構造。設計時によく尋ねられる6つの質問に答えます。

Q1. BrainとAgentは同じ名前である必要がありますか？

いいえ。「Finance Brain」と「Finance Agent」は分かりやすさのために同じ名前を冠していますが、全く別の存在です。1つのFinance Brainを3つのAgent（Shopping / Tax / Budget）で共有することもできます。逆に、1つのCalendar Agentが5つのBrain（Finance / Education / Health / Calendar / Household）から読み取ることも通常想定される設計です。

Q2. Brain単体でAIを機能させることはできますか？

いいえ。Brainは本棚のようなものです。それを読み取る者（Agent）と、誰が何を読み取るかを決める者（Coordinator）がいなければ機能しません。逆に、Agent単体では共有メモリが存在しないため、すべてのセッションが毎回ゼロからスタートすることになります。これら3つが揃う必要があります。

Q3. AgentはBrainに直接書き込みできますか？

はい、ただし許可された権限の範囲内に限ります。Disclosure Dial（開示ダイヤル）とDisclosure Matrixによって、どのAgentがどのBrainにどの程度書き込めるかが決定されます。例えば、Finance AgentはFinance Brainへの完全なアクセス権を持ちますが、Person Brainには書き込みできません（プライバシー境界）。これがProject 01における「5 × 5 = 25のアクセスルール」が意味するものです。

Q4. Coordinatorは1つだけですか？

家庭の規模であれば、1つのCoordinatorで十分です。企業の規模になると、調整役の階層構造（部門Coordinator → 企業全体のCoordinator）が必要になります。重要な要件は、「全体を読み通して判断する」役割が1つ以上存在することです。

Q5. 既存のAI製品と何が違うのですか？

ChatGPTやClaudeは「Agentのみ」のモデルです（メモリは内部的かつ閉じています）。Apple IntelligenceやSamsung Family Hubは「一部のBrain ＋ 専用Agent」のモデル（家族プロファイルなど）です。

これらに対し、Context Grammarが提案するのは「分散型マルチBrain × 各レイヤーで独立した専門Agent × Coordinator」という3つの階層構造です。これこそが「自律型AI（Agentic OS）」を現実のものにするアーキテクチャです。

Q6. 3つのレイヤーは、すべてのBrainに本当に存在するのですか？

はい、常に存在します。例えばPerson Brain（Sota）なら、「11歳・サッカー」（Identity）、「最近足が急成長」（Learning）、「今朝靴がきついと発言」（Now）となります。Finance Brainなら、「通貨 JPY」（Identity）、「今月は外食が多い」（Learning）、「残高 ¥23,000」（Now）です。旅行などのEvent Brainであっても、「日程・人数」（Identity）、「Kaiはラーメンが好き」（Learning）、「現在京都駅にいる」（Now）となります。レイヤー構造は、すべての記憶（Brain）における普遍的な解剖学（仕組み）です。

信頼の制御なきメモリは、ただの監視になる。
