AX Patterns

Agentic interfaceのための23の名前付き行動です。Rule Engineが発火したあと、AIがどう委任し、戻し、適応し、説明するかをAX Patternsが定義します。

01 すべてのPatternにはToken triggerがあります。
02 Patternはドメインとデバイスをまたいで再利用できます。
03 複数Patternは、1つの体験として合成されます。

定義

Patterns are techniques, not recipes.

Patternは、デバイス非依存、Signal-triggered、再利用可能である必要があります。

Recipeは何を作るかを示します。Techniqueはどう振る舞うかを示します。Context GrammarのRulesはAIが何をすべきかを決め、AX Patternsはその行動がどのように実行されるべきかを記述します。

レストランで言えば、menuは厨房に何を作るかを伝えます。Service techniqueは、それをどうテーブルに運ぶかを決めます。料理を説明する、アレルギーを確認する、黙って水を足す、managerを呼ぶ。AX PatternsはAI behaviorにおけるこの技術集です。

Test 1

Signal condition?

特定のSignal値で発火できること。「なんとなく良さそう」はPatternではなくheuristicです。

Test 2

Reusable across contexts?

Grocery、travel、enterprise approvalsなど、複数ドメインで成立すること。

Test 3

Device-independent?

Interaction logicがform factorをまたいで保たれること。スマホだけで成立するならcomponentです。

Pattern vs. not a pattern

名前付き行動には、trigger、reuse contract、success conditionが必要です。

Pattern

D4 Omakase Mode

Autonomy = Auto、Disclosure = Full、Brain L2 trustが高いときにだけ有効になる完全委任。triggerが明示されているため、grocery、scheduling、travel、enterpriseで再利用できます。

Not a pattern

"Smart suggestions"

AIが「自信がありそう」なときに提案するだけでは、trigger、form、success criterionがありません。テストも再利用もできません。

カテゴリ

Four categories, 23 patterns.

すべてのPatternは、Delegation、Escalation、Adaptationという3つの基本方向のどれかに属します。Enterprise patternsは、監査や複数人利用のためにその方向へ追加制約を加えます。

レストランで言えば、Delegationは常連客の好みを学ぶこと。Escalationは「少し確認します」と人間へ戻すこと。Adaptationは照明、席間隔、menu表示を場面に合わせること。Enterpriseは200人の宴会を記録付きのhandoffで回すことです。

組み合わせ

Patterns compose into one behavior.

Silent Resolution: orderは完了し、1 itemだけ保留され、朝の流れは邪魔されない。

D4 Omakase Mode

火曜の朝。Autonomy = Auto、Disclosure = Full、groceryに対するBrain L2 trustが高い。weekly orderは人を止めずに走ります。

D6 Dynamic Friction

あるsupplementが品切れで、代替品は¥4,800。Hanaのitem thresholdを超えているため、そのitemだけauto-executionを止めます。

E5 Trust Breach Recovery

Hanaは代替品を拒否します。E5はそのsignalをBrainに記録し、このcategoryのAutonomyを1段階下げます。

A2 Cognitive Scaling

school drop-off後、Cognitive Loadが下がるまで待ちます。その後、「元ブランドを待つ」か「今週はskip」の2択だけを出します。

Why a library

Libraryは、shared contractです。

Listは単なる集合です。Libraryは、shared name、trigger condition、test expectation、composition ruleをチームに与えます。D1 Approval Gateが複数productで同じ意味を持てば、ユーザーは6つの別モデルを学ばずに済みます。

Specsはこれを正しく実装するための詳細です。signal resolution、priority logic、schema shape、integration contracts、test cases。Pattern namesはdesignとengineeringの共通語になります。

Q&A

Common questions.

Product teamが独自Patternを作れますか？

できます。ただし、shared nameとtrigger conditionがなければ、再利用も、spec参照も、testもできません。3-question filterを通る新しい行動ならlibraryに追加できます。

DirectionとPatternの違いは？

DirectionはhumanとAIの大きな関係です。Delegation、Escalation、Adaptation。Patternは、その中にある名前付き・trigger-definedなinteractionです。

23 patternsで全部ですか？

いいえ。これはProjects 1-5時点のcatalogです。既存Patternの組み合わせでは説明できないdesign scenarioが出たとき、新しいPatternを追加します。
