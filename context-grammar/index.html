Framework Overview

The whole framework in 60 seconds

Context Grammar has three working layers and four supporting elements. Together they describe everything an agentic system needs to understand a person and respond well.

What you want
Intent

Explicit requests and implicit goals — what you're actually trying to achieve, not just what you typed.

8 Context Tokens
Situational state

The 8 variables that describe your current situation: Physical State, Cognitive Load, Social Exposure, Priority Weight, Form Factor, Feasibility — plus 2 trust dials.

5-Brain Model
Structured memory

Five Brain types (Household, Person ×5, Domain ×N, Coordinator, Event ×N), each with three layers: Identity · Learning · Now.

2 Trust Dials
Human control

Autonomy Dial — how much you delegate. Disclosure Dial — how much you share. Both are per-domain. Both are user-owned.

Rule Engine
Decision logic

Turns tokens + memory into design rules. Resolves collisions. Emits specific instructions that AX Patterns can act on.

23 AX Patterns
Interface behavior

Named patterns — D1–D6, E1–E5, A1–A8, X1–X4 — that describe how UI surfaces should respond when the Rule Engine fires.

How They Connect

One signal, six transformations

A real interaction passes through all six elements. The request enters as Intent. Tokens describe the situation. Brain supplies memory. Rule Engine resolves conflicts. AX Patterns shape the interface. Specs make it portable.

01
Intent arrives

Explicit: "Order pizza." Implicit: the system infers "wants dinner sorted quickly" from calendar density + low energy signals. Intent is the destination — everything else helps navigate to it.

02
8 Tokens capture the situation

Physical State (tired, 21:30, home), Cognitive Load (high — three meetings today), Social Exposure (home alone), Feasibility (Deliveroo is open, payment is confirmed). Six situation tokens describe what is real right now.

03
Brain supplies memory

Identity Layer: gluten allergy, two favourite restaurants. Learning Layer: orders Japanese on Fridays, hates delivery minimums. Now Layer: current token values merged with real-time calendar and location.

04
Rule Engine emits design rules

Autonomy Dial is at Confirm. Cognitive Load is high. Rule: do not show a list of 40 restaurants — pre-select one, show a single confirmation. Collision between "user prefers to choose" and "load is too high to choose tonight" is resolved here.

05
AX Patterns shape the interface

Pattern A3 — Confident Suggestion — fires. One card, one tap to confirm. No navigation, no search, no menu browsing. The rule has already made the decision. UI is just confirming it.

06
Specs make it portable

The YAML schema for this interaction — Token values, Brain state, rule output, AX pattern ID — can be handed to any surface: phone, TV, fridge, CarPlay. Same intent, adapted form.

Floor 3 · Brain

Five Brain types. Three layers each.

A household is not one mind. The fridge knows about food. The calendar knows about time. Each person has their own memory. Context Grammar models this as five distinct Brain types, each with the same three-layer anatomy: Identity · Learning · Now.

01
Household Brain

Shared memory — house rules, family structure, shared assets, utility accounts.

02
Person Brain ×5

One per person — individual preferences, health, relationships, schedule patterns.

03
Domain Brain ×N

One per life domain — Finance, Health, Work, Travel. Holds domain-specific rules and history.

04
Coordinator Brain

Reads all other Brains. Resolves conflicts. Dispatches Agents. The conductor, not a performer.

05
Event Brain ×N

Time-limited memory for a trip, a renovation, a project. Born → learns → merges back → dissolves.

Universal anatomy — every Brain has three layers

Identity Layer — who this Brain is. Months to years.  ·  Learning Layer — patterns accumulated from repetition. Days to weeks.  ·  Now Layer — current token values, active intent, real-time context. Seconds to minutes.

Floor 5 · AX Patterns

23 patterns, four groups

When the Rule Engine emits a decision, something in the UI must respond. The 23 AX Patterns are the named vocabulary for that response — making design decisions repeatable and reviewable across teams and surfaces.

Group D
Delivery
D1–D6 · 6 patterns

How the system delivers output — notification timing, surface choice, verbosity level, interruption threshold.

Group E
Escalation
E1–E5 · 5 patterns

When and how to escalate from silent action to full confirmation — trust breach recovery, ambiguity resolution, override flows.

Group A
Autonomy
A1–A8 · 8 patterns

Dial-specific behaviors — what "Suggest," "Confirm," "Notify," and "Auto" each look like in the interface. The four Autonomy stages, named and specified.

Group X
Cross-cutting
X1–X4 · 4 patterns

Patterns that apply regardless of group — multi-person coordination, graceful degradation, session continuity, surface handoff.

FAQ

Common questions answered

Is Context Grammar a product, a framework, or a spec?

It is a design language — comparable to how Material Design is a design language, not a component library. Context Grammar names the concepts, defines their relationships, and provides schemas that can be implemented in different ways on different platforms. It is not tied to a specific OS or AI provider.

How is this different from a regular AI memory system?

Most AI memory systems store facts as a flat list — unstructured text with no distinction between "who you are" and "what you just did." Context Grammar adds three things: structured layers (Identity / Learning / Now), multiple Brain types per household (Person, Domain, Coordinator, Event), and a design vocabulary — Tokens, Dials, Patterns — so the memory can drive consistent interface decisions across surfaces and teams.

What are the 2 Trust Dials and why are they separate from the 8 Tokens?

The Autonomy Dial controls how much the AI decides without asking (four stages: Suggest → Confirm → Notify → Auto). The Disclosure Dial controls how much personal context the AI can access per domain. Both are treated as Tokens in the 8-Token count because they are live signals that shape every decision — but they are relationship settings, not situational measurements. The distinction matters for design: the other six Tokens are read-only observations; the two Dials are user-owned controls.

Is this speculative design or is it implementable today?

Mixed. Some parts are shipping today — Autonomy Dial stage logic is standard in agent frameworks. Form Factor and Social Exposure Tokens are trivially readable. Other parts require inference — Cognitive Load is estimated from calendar density and time-of-day patterns, not directly measured. The Specs page distinguishes each element by current technology readiness.
