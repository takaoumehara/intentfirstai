Context Grammar · Concept Explainer · 平易な日本語で

Brain と Agent は
別ものです。

違いが分かると、AI の「分散認知システム」がスッキリ理解できます。
Sota の靴を買うシーンで、6つの Brain と1つの Coordinator がどう動くかを追跡します。

§1

まず根っこから — Brain は「記憶」、Agent は「行動者」

多くの人が「Finance Brain」と「Finance Agent」を同じものと混同します。実は全く別のものです。図書館の本と司書ぐらい違います。

📚
Brain
記憶

情報をしまっておく場所。自分からは何もしない。読まれたら出す、書かれたら覚える。それだけ。

  • 家族のアレルギーを覚えている
  • 11ヶ月分の月曜パターンを蓄える
  • 誰がアクセスできるかルールを持つ
  • 「忘れない」のが仕事
vs
🏃
Agent
行動者

人と話す、判断する、行動する AI。Brain から情報を読んで決める。学んだら Brain に書き戻す。

  • 「これ買っていい？」と人に答える
  • Amazon でシューズを注文する
  • 通知を送る、メールを書く
  • 「動く」のが仕事
覚え方: Brain は名詞（記憶という物）。Agent は動詞（記憶を使って動く者）。
§2 · 比喩

レストランで考えてみる

「Brain」と「Agent」を、レストランの世界に置き換えると一発で分かります。

🍽 レストランの裏側で起きていること

📚 Brain (記憶) = 書類・本・台帳

そこにあるだけ。自分から動かない。

・レシピブック
・お客様カルテ（アレルギー、好み）
・在庫表
・衛生管理マニュアル

🏃 Agent (行動者) = 動く人々

本を読んで、考えて、行動する。

・シェフ（レシピを読んで料理を作る）
・ホール係（お客様カルテを見て案内する）
・ソムリエ（在庫表を見てワインを薦める）
・マネージャー（全部見て判断する＝Coordinator）
レシピブックは何もしません。シェフが本を読んで料理を作ります。
Brain は本。Agent はシェフ。
マネージャー（Coordinator）は全部読んで誰に何をやらせるか決める人。
§3 · 実例

Sota の靴 $48 を買う — 6つの Brain が動く

日常の何気ない判断ひとつで、家庭のどれだけの記憶が動員されているかを追ってみましょう。

「お母さん、サッカーシューズきつい！」

— Sota (11歳・サッカー部) · ある火曜の朝

1 Sota が話す Voice Agent
Sota は朝食で母 Mai に言う。
Voice Agent（音声を聞いている AI）が会話を聞き取り、"shoes too tight" という事実を Coordinator に伝える。
2 Coordinator が考える — 5つの Brain を読みに行く Coordinator
Coordinator は「Sota のシューズを今すぐ買うべきか？」を判断するため、5つの Brain を順番に読みに行く。 これは1秒もかからない。
📚 Brains が answers を返す
  • Person Brain
    (Sota)     11歳・soccer Tuesday 必須・今の足サイズ EU 36（最近5mm 伸びた）
  • Finance Brain 今月の予算残り $230・"子供必需品" 枠 $150 残り・$50 以下なら自動承認 OK
  • Education Brain School dress code OK・PE class で必要
  • Calendar Brain 来週土曜に試合あり・急ぎ
  • Household Brain 家のルール: "子供の必需品 $50 以下 → silent buy OK"
→ 結論: SILENT BUY (auto-approve, ログだけ記録)
3 Shopping Agent が買う Agent
Coordinator が Shopping Agent に指示。
Shopping Agent は Sota のサッカーチームが指定するブランド + 適切なサイズで Amazon に注文する。$48 + 即日配送 = 完了。
4 Brain たちが学ぶ — 結果を書き戻す Brains
行動が完了したら、Agent は学んだことを Brain に書き戻す。
  • Finance Brain$48 子供必需品費 を記録、月次予算に反映
  • Person Brain (Sota)足サイズ EU 36 を identity layer に書き換え
  • Household Brain"silent buy" ルールが正しく機能した、と Learning layer に記録
5 Mai の iPhone に「報告」が出る Result
Mai は何も判断しなくていい。事後報告だけ。
"Sota's soccer shoes ordered. Auto-approved. $48. — Tap to undo."

これが Silent Resolution の正体。Mai が朝の決断地獄から解放される。
気づきポイント: Sota の一言で、5 つの Brain・1 つの Coordinator・3 つの Agent（Voice / Shopping / Notification）が連携した。誰一人プログラミングの知識を必要としていない。家族はただ普通に話しただけ。
§4 · 関係性

Brain と Agent の関係 — 1対1ではない

1つの Brain を複数の Agent が読む。1つの Agent が複数の Brain を読む。これが正しい使い方。

情報の流れ — Sota の靴を買うシーンで（アニメーション再生中）
Static fallback
3つのパターンが同時に起きている:
① 1つの Brain (Person Brain) を複数の Agent が読む
② 1つの Agent (Coordinator) が複数の Brain を読む
③ Agent が学んだら Brain に書き戻す（記憶の更新）
§5 · ベースモデル

どんな規模でも通用する 5 階層

1人の個人から、家族、スタートアップ、大企業まで — 同じ 5 階層で記述できる。違うのは「N の数字」だけ。

家族の 5 階層 — Yamashiro 家の場合
Tier 役割 個人 (1人) 家族 (5人) スタートアップ (30人) 大企業 (1000+)
1 永続土台 Self Brain Household Brain Org Brain Org Brain
2 判断 DNA — Person × 5 Person × 30 / Brand × 1 Brand × N（多商品・地域別）
3 専門知識 Health / Money / Schedule (3) Domain × 5（Finance / Edu / Health / Cal / Home） Function × 3-4（Ops / Customer / Finance） Function × 8-12（Legal / HR / Finance / Marketing / Sales / Eng / Customer / Research / Ops…）
4 司令塔 (自分の脳) Household Coordinator PMB PMB hierarchy
5 時限実行 Trip / Move Event × N Project × few Project × many
キーポイント: 5 階層は不変、N が変わるだけ。家族の Domain は 5、大企業の Function は 12。でも「専門知識を持つ脳が並列に存在する」構造は同じ。
Agent は別レイヤーで可変。スタートアップは 3 Agent で兼任、大企業は 12 Agent に分業。

§7 · よくある混乱

よくある質問を整理する

Q1. Brain と Agent は名前を同じにしないとダメ？
いいえ。 「Finance Brain」と「Finance Agent」は分かりやすさのため名前を揃えてるけど、別物。1つの Finance Brain を Shopping Agent / Tax Agent / Budget Agent の3つが共有してもいい。逆に、Calendar Agent 1つが Finance / Education / Health / Calendar / Household の 5 つの Brain を読むこともある。
Q2. Brain だけあれば AI は動かないの？
動きません。 Brain は本棚と同じ。中身を読む人（Agent）がいないと意味がない。一方、Agent だけだと記憶が共有できない（毎回同じ説明を求められる）。両方必要。
Q3. Agent が直接 Brain を書き換えていいの？
はい、ただし権限がある範囲で。 Disclosure Dial / Disclosure Matrix が、どの Agent がどの Brain にどこまで書き込めるかを決める。Finance Agent は Finance Brain にフルアクセスだけど、Person Brain には書き込めない（プライバシーの境界）。これが Project 01 で説明した 5 × 5 = 25 のアクセスルールの意味。
Q4. Coordinator は1つだけ？複数あってもいい？
家庭サイズなら1つで十分。大企業になると Coordinator のヒエラルキーが必要（部門長 Coordinator → 全社 Coordinator など）。基本的には「読み合わせて判断する役」が1つ以上あればいい。
Q5. これって既存の AI と何が違うの？
ChatGPT / Claude は Agent だけのモデル（記憶を内部に閉じこめている）。Apple Intelligence / Samsung Family Hub は少しの Brain + 専用 Agentのモデル（家族プロファイルなど）。
Context Grammar が提案するのは分散した複数の Brain × 別レイヤーの専門 Agent × Coordinator という3層構造。これが "agentic OS" の正体。
