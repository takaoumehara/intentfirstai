Definition

Patterns are techniques, not recipes.

A pattern is device-independent, Signal-triggered, and reusable.

A recipe says what to cook. A technique says how to work. Context Grammar's Rules decide what AI should do. AX Patterns describe how that behavior should be executed, regardless of the product surface.

In restaurant terms, the menu tells the kitchen what to cook. Service technique decides how the waiter brings it to the table: describe the dish, check allergies, silently refill the glass, or call the manager. Skilled teams reuse those techniques with many guests. AX Patterns do the same for AI behavior.

Test 1

Signal condition?

A specific Signal or Dial value should trigger it. "When it feels right" is a heuristic, not a pattern.

Test 2

Reusable across contexts?

It should work across domains such as grocery, travel, and enterprise approvals.

Test 3

Device-independent?

The interaction logic should hold across form factors. If it only works on phones, it is a component.

Pattern vs. not a pattern

A named behavior needs a trigger, a reuse contract, and a success condition.

Pattern

D4 Omakase Mode

Full delegation to AI, activated only when Autonomy = Auto, Disclosure = Full, and Brain L2 trust is high. It works in grocery, scheduling, travel, or enterprise because the trigger is explicit.

Not a pattern

"Smart suggestions"

Shows a suggestion when AI "feels confident." There is no defined trigger, consistent form, or success criterion, so product teams cannot test or reuse it.

Categories

Four categories, 23 patterns.

Every pattern belongs to one of three core directions: Delegation, Escalation, or Adaptation. Enterprise patterns extend those directions for audit-heavy, multi-person systems.

Delegation is the waiter learning a regular guest's preferences. Escalation is saying, "I'm not sure; let me check." Adaptation is changing lighting, spacing, or menu format. Enterprise is the banquet team running 200 covers with documented handoffs.

D · 6 patterns

Delegation

Handing authority to AI. Trust is the prerequisite, so these patterns measure trust and act within risk limits.

E · 5 patterns

Escalation

A · 8 patterns

Adaptation

Changing the interface with context. Content may stay the same while form, density, and visibility shift.

X · 4 patterns

Enterprise

Patterns for multi-person, compliance-heavy, or audit-required contexts. They use the same directions with stronger trust requirements.

Execution contract

Agent Action Lifecycle

The pattern library defines how an agent behaves at execution time. Every pattern can be tagged with a primary lifecycle verb so design and engineering can reason about action shape before UI detail.

Verb Meaning in execution Typical AX use
Inform Make state, confidence, or provenance visible. Confidence Signal, Source Attribution, Limitation Disclosure.
Recommend Propose a direction while preserving user decision authority. Approval Gate, Proactive Nudge, Ambiguity Escalation.
Plan Draft a multi-step approach before committing to irreversible work. Substitution strategies and scenario shaping before action.
Prepare Set up context, options, and draft artifacts for a later decision. Inline Edit and Disposable Surface setup flows.
Act Execute directly within trust and risk constraints. Omakase Mode and low-risk auto-execution moments.
Monitor Observe outcomes, trust drift, and policy boundaries over time. Progressive Trust, Temporal Handoff, Autonomy Dial governance.
Adapt Recompose outputs when context, feasibility, or social state changes. Form Factor Transform, Rollback, Live Recomposition.

Gate Matrix

The Negotiation Gate output determines which lifecycle verbs are most likely. A silent gate result usually routes to Act or Adapt. confidence_signal and interpretation_preview route to Inform and Recommend. assumption_cards routes to Recommend and Prepare. escalate and block shift control to Inform + Monitor until risk is resolved.

Composition

Patterns compose into one behavior.

Silent Resolution: the order completes, one item is held, and the morning is not interrupted.

D4 Omakase Mode

It is Tuesday morning. Autonomy = Auto, Disclosure = Full, and Brain L2 trust is high for groceries. The weekly order runs without prompting anyone.

D6 Dynamic Friction

One supplement is out of stock, and the cheapest alternative costs ¥4,800, above Hana's per-item threshold. Friction blocks auto-execution for this item only.

E5 Trust Breach Recovery

Hana rejects the substitute because she wanted the original brand. E5 records the signal in Brain and demotes Autonomy one stage for this category.

A2 Cognitive Scaling

The system waits until Cognitive Load drops after school drop-off. Then it shows two options: wait for the original brand or skip this week.

Why a library

A library is a shared contract.

A list is a collection. A library gives teams shared names, trigger conditions, test expectations, and composition rules. When D1 Approval Gate behaves the same across products, users learn one mental model instead of six.

Specs define how to build this correctly: signal resolution, priority logic, schema shape, integration contracts, and test cases. The pattern names give design and engineering a common language.

Q&A

Common questions.

Can a product team invent its own patterns?

Yes, but without a shared name and trigger condition, the behavior cannot be reused, referenced in a spec, or tested. Extend the library when a new behavior passes the three-question filter.

What is the difference between a Direction and a Pattern?

A Direction is the broad relationship between human and AI: Delegation, Escalation, or Adaptation. A Pattern is a named, trigger-defined interaction inside that direction.

Are the 23 patterns exhaustive?

No. This is the catalog as of Projects 1-5. New patterns should be added when a design scenario cannot be described by combining existing ones.
