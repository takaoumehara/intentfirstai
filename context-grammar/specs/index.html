Restaurant model

The menu and the recipe card.

When a restaurant opens another branch, the chef does not send a poetic description. They send a recipe card: chicken thigh 180 g, oil temp 78 C +/- 2, cook time 90 min, salt ratio 1.2%.

The menu helps guests understand the dish. The recipe card helps every kitchen reproduce it. Same dish, two languages, two readers.

Context Grammar works the same way. A portfolio chapter explains a scene to a designer. The Spec lets an iPhone, fridge, or car dashboard act on that scene without being briefed again.

Step by step

A Tuesday morning becomes a Spec.

"7:02 AM. Mai is making her son's lunch while getting ready for work. Cognitive load is high."

Write the narrative

A person can read the sentence. It carries context, emotion, and story, but it does not tell an iPhone how to behave.

Find the Signals

Cognitive Load is high, Physical State is hands busy, Social Exposure is family-private, and Form Factor is kitchen iPhone.

Write the Spec

The same scene becomes structured data with signal values, confidence, source, and projection rules.

Devices render

The iPhone uses voice and one step. CarPlay would use voice only. The Spec stays stable; the surface translation changes.

Narrative and Spec agree

"Mai is overwhelmed, hands full" equals cognitive_load=0.82 and physical_state=hands_busy. A mismatch is a design bug.

Example JSON contract 
{
  "context_id": "mai-tuesday-morning",
  "spec_version": "v1.2",
  "tokens": {
    "cognitive_load": {
      "value": 0.82,
      "confidence": 0.74,
      "source": "calendar+activity+time-of-day"
    },
    "physical_state": {
      "value": "hands_busy",
      "confidence": 0.91,
      "source": "kitchen-presence+cooking-activity"
    },
    "social_exposure": {
      "value": "family_private",
      "confidence": 0.99
    }
  },
  "projection_rules": {
    "voice_priority": true,
    "text_density": "low",
    "interaction_steps": "max_1"
  },
  "ui": {
    "command": {
      "mode": "confirm",
      "label": "Book the piano trial",
      "requires_human": true
    }
  }
}

Universal contract

The same Specs flow from every Brain.

Specs are defined per Signal or Dial, not per Brain. Whether the Spec originates from a Person Brain, Domain Brain, Household Brain, or Project Brain, the structure is identical.

Brain is the memory entity. Spec is the output format. Switching from Home Brain to Enterprise Brain changes the memory model, not the Spec schema.

Design contract

Why YAML? Why Decision Schema?

Every Signal and Dial in Context Grammar carries more than a value. It carries: where the value came from, how confident the system is, what the fallback behavior is when the signal is unavailable, and how production-ready the implementation is today.

This transforms Context Grammar from a "sensor spec" — a list of things the AI should detect — into a decision contract: an explicit, inspectable record of what the AI knows, how certain it is, and what it will do when it doesn't know. The contract is the design artifact. An engineer can read it and know exactly how the system will behave under uncertainty.

YAML makes the schema human-readable without requiring a runtime system. The spec can be reviewed, revised, and debated before any implementation exists.

Machine enforcement

Schema + SDK + ui.command

context-grammar.schema.json validates ContextState. context-grammar.d.ts and the SDK expose typed evaluation. ui.command proves that a Spec can request a concrete UI action.

Forward compatibility rules
Rule Reason
Add new fields Always allowed. Old surfaces ignore unknown fields.
Delete fields Never allowed. Keep an alias instead.
Change a field's meaning Never allowed. Rename the new concept instead of redefining the old one.

Spec anatomy

Five fields every Spec must include.

Field What it declares Example
token_id Which Signal or Dial this entry describes. cognitive_load
value The Signal's current number, enum, or range. 0.82
confidence How certain the estimate is. 0.74
source Where the value came from. calendar+activity+time-of-day
projection_rules Hints passed to the UI layer. voice_priority: true
