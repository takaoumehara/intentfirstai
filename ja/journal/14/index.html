エッセイ — 14

何を委ねるか、何を握るか。その境界線が動く理由

自律マップと自律ダイアルは別物だ。どちらも、信頼が積み上がるにつれて動いていく。

2025

あなたはすでに体験している

Netflix

あなたのNetflixのホーム画面は、友人のホーム画面とまったく違う。

同じ映画なのに、見える顔が違う。あなたにはロマンスシーンのサムネイルが、友人にはアクションシーンのサムネイルが出る。Netflixは一作品につき何十枚ものサムネイルを用意して、その一枚ごとに「この人がクリックする画像はどれか」を判断している。

あなたが見ているコンテンツの80%はレコメンデーション経由だ。自分で選んでいるのは20%しかない。

あなたは自分で決めているつもりでいる。実際に決めているのはNetflixだ。

Amazon

いまAmazonを開いてみる。ホームページに並ぶ商品はすべて、あなた一人のために並べられている。

「もう一度買う」を使ったことがあるはずだ。先月、ドッグフードを注文した。ワンクリックで再注文。その前は、検索して、スクロールして、正しい商品を見つけて、カートに入れて、確認していた。いまはワンクリックで終わる。

Amazonの売上の35%は、このレコメンデーションエンジンから生まれている。一日に1,500億のデータポイントを処理して、次にあなたが何を買うかを予測している。

Spotify

月曜の朝、Discover Weeklyを開く。30曲。聴いたことのない曲ばかり。それなのに、どういうわけか、まさにいま聴きたかった曲ばかりだ。

最初の3曲で、つい思う。「なぜ分かったのか」。

Spotifyは、あなたのテイストプロファイルを一つだけ持っているのではない。複数持っている。ワークアウト中に聴く音楽と、日曜の朝にコーヒーを飲みながら流す音楽は別物だ。だから複数のMixが届く。それぞれ、別バージョンの「あなた」にチューニングされている。

使えば使うほど、精度が上がっていく。

このパターンには名前がある

この三つのサービスには共通点がある。

AIに委譲されているもの：

Netflix  → 何を観るかのレコメンド
Amazon   → 過去に購入したものの再注文
Spotify  → まだ知らない曲の選定

あなたが依然として決めているもの：

Netflix  → 実際に観るかどうか
Amazon   → 実際に買うかどうか
Spotify  → 聴き続けるかスキップするか

委譲と所有の間の境界線。それが自律マップ（Autonomy Map）だ。

だが、委譲された側の中にも、レベルがある。

Netflix  → ホーム画面を自動で変更する（高い自律性）
Amazon   → 「もう一度買う」を表示するが、押すのはあなた（中程度）
Spotify  → 知らない曲を追加するが、スキップは自由（中程度）

このスペクトラム──どこまで委譲しているか──が自律ダイアル（Autonomy Dial）だ。

マップとダイアルの正体

委譲                        所有
情報収集                    最終判断
・検索と比較                ・価値観に基づく判断
・パターン学習              ・金額の確認
・送信／公開

← 自律マップ →

自律マップ：境界線をどこに引くか。何を委譲し、何を自分の手元に残すか。

自律ダイアル：委譲した側について、どこまで自律的に動かすか。ポジションは四つある。

提案        →  確認        →  通知        →  自動

いきますか？」 進めて        た」           が完全に
いいですか？」 （取消可能）   処理

ツールを使うその瞬間、委譲はすでに始まっている。Googleマップを開いた瞬間、ルート計算はもう委譲している。だから使う。マップなしのダイアルは意味をなさない。そしてダイアルなしのマップは、ただ許可を求め続けるだけだ。

名前をつけると見えてくるもの

Netflix、Spotify、Amazon。すでに大規模にこれを実装している。Spotifyはあなたのテイストの複数バージョンを把握している。Netflixはサムネイル単位でパーソナライズしている。Amazonは売上の35%をレコメンデーションエンジンから得ている。Bettermentのようなロボアドバイザーはポートフォリオ全体を「自動」で運用している。

マップとダイアルは発明ではない。すでに存在するパターンに名前を与える「言語」だ。

ではなぜ、名前をつけることが大切なのか。言語を持って初めて、まだ存在していないものが見えてくるからだ。

洞察1：ダイアルの天井は領域によって変わる

2021年、Netflixは「Play Something」（のちに「Surprise Me」に改名）をリリースした。AIが番組を選ぶ。再生が始まる。入力は要らない。

利用率があまりに急速に落ちたため、2年後に廃止された。

なぜか。エンタメの領域では、「何を観るか選ぶこと」そのものが体験の一部だからだ。選ぶ行為を委譲すると、その価値が壊れる。

一方、Amazonのスマートリオーダーは機能している。洗剤が少なくなれば自動で再注文される。文句を言う人はいない。洗剤を選ぶことは体験ではなく、雑用だからだ。

領域ごとのダイアル天井：

日用品の補充：          天井 = 自動
→ 選ぶことに意味がない。Amazonスマートリオーダーが機能する理由。

エンタメ：              天井 = より良い提案
→ 選ぶことが体験そのもの。Surprise Meが失敗した理由。
→ AIの仕事は選ぶことではない。正しい選択肢を最初に浮上させることだ。

金融（ルーティン）：    天井 = 自動
→ 自動積立、自動予算管理、支出の自動カテゴリ分類。

金融（高リスク）：      天井 = 確認
→ 新規投資、大口送金、ローン。

注目してほしい。金融に天井は一つではない。毎月の自動積立は「自動」で動く。でも、10,000ドルを新しいファンドに入れるとなれば、決めるのはあなただ。同じカテゴリ、別のタスク、別のダイアル設定。これは先のエッセイで挙げた四つの次元、可逆性・親密度・賭けの大きさ・コンテクストにつながっている。ダイアルの天井は、その組み合わせで決まる。

洞察2：暗黙のダイアルと明示的なダイアルは同じではない

Netflix、Spotify、Amazonのレコメンデーションは、勝手に改善されていく。あなたは何も設定していない。ただ使っているだけだ。これが暗黙のダイアル（Implicit Dial）。観察を通じて勝手に上がっていく。

一方、Amazon Auto Buyはあなたが設定する。「この商品の価格が15ドルを下回ったら自動購入する」。意識的で、意図的だ。これが明示的なダイアル（Explicit Dial）。自分でダイアルを回す。

暗黙のダイアル（行動を通じて上昇）：
→ Netflix：視聴するほどレコメンデーション精度が向上
→ Spotify：Discover Weeklyが毎週良くなる
→ ロボアドバイザー：学習によりポートフォリオのリバランスが最適化

明示的なダイアル（意図的に設定）：
→ Amazon Auto Buy：「15ドル以下で自動購入」
→ Tesla FSD：SlothモードかMad Maxモードを選択
→ Google Personal Intelligence：アプリごとにGmailアクセスを許可/ブロック

どちらが正しいのか。両方が必要だ。ルールはシンプル。

低リスク、容易に可逆 → 暗黙のダイアルで十分
→ レコメンデーション、プレイリスト、検索品質
→ 間違い？ スキップするか、戻るだけ。

高リスク、取り消し困難 → 明示的なダイアルが必須
→ 購入、送信、予約
→ 間違い？ もう遅い。

洞察3：サービス横断の学習はまだ存在しない

Spotifyはあなたの音楽の好みを知っている。Amazonは買い物のパターンを知っている。Netflixはエンタメの好みを知っている。でもあなたを丸ごと知っているシステムは、まだ一つもない。

月曜の朝、Spotifyでジャズを流す。Amazonでプレミアムコーヒー豆を注文する。Netflixで料理番組を観る。そこに走っているのは「リラックスした朝のリチュアル」という一本の糸だ。でも、その糸を見ているシステムはない。各サービスは、自分のサイロの中だけで最適化している。

ここで、「家政婦」の例が効いてくる。

本物の家政婦はあなたの生活全体を見ている。冷蔵庫、パントリー、家族の好み、来週のスケジュール。一つのカテゴリだけを切り離して最適化しない。家全体を横断して学習していく。Spotifyにできることでも、Amazonにできることでもない。

洞察4：開示ダイアル ── 委譲の前に、開示がある

ここまで見てきたすべてのパターンの下には、もう一つの前提条件が埋まっている。

開示していないものは、委譲できない。

Netflixのレコメンデーションは視聴履歴があるから成立する。Spotifyのプレイリストはリスニングデータから組み上がる。Amazonの「もう一度買う」は購入履歴を必要とする。サービスを使うこと自体が、暗黙のうちに開示する行為になっている。

これを家庭に持ち込むと、もっと意図的な営みになる。家族の食事制限、好み、アレルギー、こだわり。利用ログからは見えてこない情報だ。明示的に共有する必要がある。

これを私は開示ダイアル（Disclosure Dial）と呼んでいる。AIにどこまで自分を知らせるかを、領域ごと、人ごとに調整する仕組みだ。

開示ダイアルは自律ダイアルの前提条件にあたる。開示が浅い領域では、AIがどれだけ高性能でも、自律性には自然な天井がある。十分に開示した領域では、より高い自律性が可能になり、ユーザー自身もそれを望み始める。

このあとの家政婦の例で、開示のプロセスが時間とともにどう展開するかを見てほしい。

家政婦を雇ったと想像する

初日。

「砂糖はどこに置いてありますか。塩はどのブランドですか。娘さんは牛乳を飲みますか」。

すべて、あなたが教えなければならない。買い物は委譲した。雇った理由がそれだ。でも「何を買うか」は、まだ完全にあなたの判断のままだ。

1ヶ月目：学習が始まる

マップのシフト：
委譲：玉ねぎのブランド、ヨーグルトの種類、補充タイミング
所有：今週の献立、特別な食材

ダイアル：
玉ねぎ → 提案（「また甘い玉ねぎでいいですか？」）
ヨーグルト → 提案（「いつもの3種類ですか？」）

3ヶ月目：家庭を学習し始める

彼女が気づいたこと：
あなたの妻：Trader Joe'sのハニーヨーグルト（これだけ）
あなた：無脂肪ギリシャヨーグルト（ブランドは柔軟）
子供：乳製品フリーのヨーグルト（どのブランド、どの味でもOK）

リブアイステーキ：このスーパーにはリブアイが2〜3パックあるが、
あなたに合う特定のパッケージは一つだけ。
他は合わない。

玉ねぎ：甘い玉ねぎがベース。売り切れなら、
黄色か白でいい。
紫の玉ねぎ？ 絶対にダメ。

ダイアルが上昇中：
ヨーグルト（3種類）→ 確認（「いつもの3つ、いいですか？」）
リブアイ         → 確認（「見つけました。買いますか？」）

6ヶ月目：代替モードが出現する

ここから面白くなる。ダイアルが上がっていくにつれて、新しいものが姿を現す。代替のルールだ。

これはレベルではなく、モードだ。良い・悪いの話ではなく、性質の違う指示が要るという話だ。アイテムごとに、AIは違う種類の指示を必要とする。

モード：フレキシブル（Flexible）

玉ねぎ → 甘い玉ねぎが標準。
売り切れなら、黄色か白でいい。
紫？ ダメ。

あなたのヨーグルト → 無脂肪ギリシャ。
ブランドはあまり気にしない。
そのタイプのギリシャヨーグルトなら何でもいい。

→ AIが代替して通知する。
→ 「甘い玉ねぎが売り切れだったので、黄色にしました」

モード：エグザクト（Exact）

妻のヨーグルト → Trader Joe'sのハニーヨーグルト。
この商品だけ。他の味ではない。
他のブランドでもない。
ただし：大サイズが売り切れなら、小6個はOK。

リブアイ → この特定のパッケージ。
他のリブアイはダメ。一切。
なければ買わない。

ビタミン剤 → このブランドだけ。

→ AIは代替しない。入手不可なら、買わない。
→ 事前承認された代替（サイズなど）だけが実行される。

同じモードでも、柔軟性の度合いは異なる。妻のヨーグルトは「ブランドと味は絶対、サイズだけは柔軟」。リブアイは「妥協ゼロ」。こうした細かな差を、AIは時間をかけて学習していく。

モード：エクスプローリング（Exploring）

プロテインパウダー → ホエイが標準。
でもいま積極的にテスト中。
先週：ダブルチョコレート。今週：バニラ。
来週：別のものを試す。

良い：バニラ（スムージーの味を邪魔しない）
悪い：ストロベリー、キャラメル（甘すぎる）
気になる：同タイプの別ブランド

→ AIがフィードバックを時系列で記録する。
→ 「前回バニラが好評でした。同じブランドの無味を試しますか？」
→ 一つに固定されない。選択肢をローテーションできる。

エクスプローリングモードは進行中のプロセスだ。積極的に試し、感想をフィードバックし、AIがそれを学んでいく。最終的にフレキシブル（「この3つをローテーション」）に落ち着くこともあれば、エグザクト（「これが決まり」）に落ち着くこともある。モードは固定ではない。遷移していく。

モード：サプライズ（Surprise）

日本のスナック → このカテゴリが好きだから、知らないものを持ってきて。
カリカリ。甘すぎないもの。
その範囲内なら何でもいい。

→ AIが基準内で未知の選択肢を選ぶ。
→ あなたの反応を記録する：「これは当たり」「これは外れ」。

ただし、すべてにサプライズが当てはまるわけではない。

日本のスナック    → サプライズで ✓
ビタミン剤       → サプライズで ✗
プロテインパウダー → エクスプローリング（新しい味）、純粋なサプライズではない

サプライズはカテゴリごとのオプトインだ。サプライズが外れたとき、それを減らしたくなる人もいれば、もっと増やしたくなる人もいる。それはもう一つのダイアル、サプライズ自体の自律性のダイアルだ。

モードは流動的だ：

エクスプローリング → 勝者を発見 → エグザクト（「ついにこれだ」）
エクスプローリング → 複数の勝者を発見 → フレキシブル（「この3つ」）
エグザクト → 飽きた → エクスプローリング（「新しいものを試そう」）
サプライズ → お気に入りを発見 → エグザクト（「これをもっと」）
フレキシブル → 好みが変わった → エクスプローリング（「いま何が食べたい？」）

好みは固定されない。季節とともに、気分とともに、体力とともに、成長とともに移り変わる。AIが学ぶのは、いま現在の好みだけではない。好みがどう変わっていくか、その動き方そのものだ。

1年後：完成したシステム

冷蔵庫は常にストックされている。
あなたは何もしていない。

何かが切れたとき → AIがモードに従う
新商品／価格変動 → 一時的に確認モード
サプライズ → 月に数回、新しいものが現れる

ある月、酸っぱいものが無性に食べたくなる。
AIがこのシフトを検知する。
あなたが何も言わなくても、サプライズカテゴリが
酸味の方向に傾く。
気づかないかもしれない。どのみち棚は変わり続けている。

これが「育てる」ということだ。

ダイアルは自動で上がるのか、自分で上げるのか？

暗黙のダイアル（Implicit Dial）。自動で上がる側だ。Netflix、Spotify、Amazonのレコメンデーションは使うほど改善されていく。何も設定していない。あなたの行動が、勝手にダイアルを回している。

明示的なダイアル（Explicit Dial）。自分で設定する側だ。Amazon Auto Buyの「この商品が15ドル以下になったら自動購入」は意図的な設定だ。Tesla FSDのモード、Google Personal Intelligenceの権限設定もそう。自分でつまみを選ぶ。

結論。両方が必要だ。どちらを使うかは、リスクが決める。

低リスク、可逆 → 暗黙のダイアル
→ レコメンデーション、音楽、サムネイル
→ 間違い？ スキップして次へ。

高リスク、不可逆 → 明示的のダイアル
→ 購入、送信、確認
→ 間違い？ もう戻れない。

家政婦の場合：

暗黙：
→ 毎週あなたが甘い玉ねぎを選ぶのを見ている。
→ 翌週、聞かずに甘い玉ねぎを持ってくる。

明示的：
→ あなたが言う。「リブアイ。この特定のパッケージだけ。
他はダメ。いいね？」
→ それは明確な指示だ。

両方が同時に起きている。観察が一つの種類の信頼を作り、直接の指示がもう一つの種類の信頼を作る。それが合わさって、関係が深まっていく。

全体像

① 自律マップ（境界線をどこに引くか）
「何を委譲し、何を自分のものにするか」
→ ツールを使う瞬間にベースラインが存在する
→ 時間とともに 所有 → 委譲 にシフト

② 自律ダイアル（委譲した中でどこまで）
範囲：提案 → 確認 → 通知 → 自動
→ 暗黙（使用を通じて上昇）
→ 明示的（自分で設定）
→ 例外時に一時的に下降

③ 代替モード（例外をどう処理するか）
委譲されたアイテムに対して、どんなパターンが支配するか？
→ フレキシブル／エグザクト／エクスプローリング／サプライズ
→ モードは時間とともにシフト

④ 開示ダイアル（AIにどこまで知らせるか）
「自分のどこまでをAIと共有するか？」
→ 領域ごと、人ごとに調整
→ 自律ダイアルの前提条件：開示していないものは委譲できない
→ 暗黙の開示（使用を通じてデータが蓄積）＋ 明示的な開示（あなたが伝える）

⑤ 信頼（四つすべてを時間とともに動かすもの）
→ 成功体験 → より広いマップ ＋ より高いダイアル
→ 失敗体験 → より狭いマップ ／ より低いダイアル
→ 想定外の事態 → 一時的なダイアル凍結

マップ = 何を
ダイアル = どこまで（自動か明示的か）
開示 = どこまで共有するか（ダイアルの前提条件）
モード = 各アイテムをどう扱うか
信頼 = いつ、どのくらいの速さで

巨大テック企業はいま、これをどう考えているか

Google ── マップとダイアルの両方を構築

Google Maps：

500回の通勤を経たあと、あなたが開いている地図アプリは初日のそれとは別物になっている。アプリを開くと、聞く前に「職場まで20分」と予測してくる（暗黙のダイアル）。渋滞は自動で迂回する。それでも、500回の通勤を経たいまも、まだ職場に向かって自動発進はしない。提案する。確認するのはあなただ。ダイアルにはまだ上げる余地が残っている。

Gemini Personal Intelligence（2026年）：

GoogleはGeminiをGmail、フォト、YouTube、検索履歴に接続している。設計原則は明快だ。デフォルトはすべてオフ。ユーザーがアプリごとにオプトインする（明示的ダイアル）。Gmailは許可、フォトはブロック。決めるのはあなただ。

GeminiのMemory機能は、会話からあなたの好みを学び、次の会話に反映する（暗黙のダイアル）。2026年2月、全ユーザーに無料で開放された。

Apple ── プライバシーでマップを拡張する

Apple Intelligenceは約30億パラメータをデバイス上で直接動かす。処理のほとんどはオンデバイスで完結する。2026年1月、AppleはGeminiとの提携を発表した。GoogleのモデルがAppleのPrivate Cloud Computeサーバー上で動く。「知能はGoogleから、データはAppleの境界の内側に」というかたちだ。

プライバシー設計が、マップを広げるエンジンになっている。データがデバイスから出ないなら、委譲への心理的抵抗は下がる。2026年後半にローンチするAgentic Siriは、メールからフライト情報を読み取り、Uberを自動予約する。その瞬間、ダイアルが動き始める。

Samsung ── コンテクストを感知する家電

CES 2026のBespoke AI Jet Bot Steam Ultra。ロボット掃除機がAI Object Recognitionで人、猫、犬、ケーブルを識別する。AI Liquid Recognitionが液体のこぼれを検知する。そして判断する。掃除するか避けるかを、あなたのルールに従って決める（明示的ダイアル）。動きは自律的でも、ルールを書いたのはあなただ。

Kitchen AI Visionは、Geminiが駆動する。冷蔵庫の中を見てレシピを提案する。「いま実際に作れるもの」を見せてくれる、現実的な実装になっている。

Microsoft ── マップを引くのはユーザーではなく組織

Copilot Control System。ここがひねりだ。自律マップを引くのは個人ユーザーではなく、組織のIT管理者になる。Copilotがアクセスできるデータは何か。実行できるアクションは何か。テナント単位、ユーザーグループ単位で設定される。個人はその境界の中でダイアルを調整する。

二つのマップが重なっている。組織のマップと、個人のマップだ。

Amazon Alexa+ ── Auto Buyとコンテクストメモリ

Auto Buy：明示的ダイアルの最もはっきりした実装だ。「Alexa、この商品が100ドルを下回ったら買って」。意図的に設定する。アイテムごとに一つのリクエスト、最大200件まで有効、24時間以内ならキャンセルできる。

コンテクストメモリは、会話を積み重ねていく。月曜に「今週はベジタリアンで」と伝えれば、木曜のディナー提案が変わる。マップが暗黙に広がる。

Tesla FSD ── シナリオと個人によるダイアル

FSDはシナリオごとに振る舞いを変える。低リスクの駐車場ではダイアル高め、高リスクの横断歩道ではダイアル低め。ドライビングスタイルもユーザーが選べる（SlothモードかMad Maxモードか）。これは明示的ダイアルだ。

新しいのはSafety Scoreだ。急ブレーキの頻度、車間距離の維持などを30日のローリング平均でスコアリングする。いまの時点では、FSDの自律性を直接変えるわけではない。それでもインフラは整っている。実績ベースで信頼が積み上がり、ダイアルが上がっていく基盤になりうる。

各社に共通するデザインの機会：

1. 段階的なマップ拡張。ツールを使い込むほど、「所有」が「委譲」へとシフトしていく。

2. 信頼に連動するダイアルの動き。うまくいった対話がダイアルを上げ、失敗が下げる。

3. 代替モード。例外はすべて同じ扱いではない。アイテムごとに固有のルールが要る。

AIプロダクトチームが見逃す三つのこと

1. マップなしにダイアルを設定する

多くのチームは「AIの自律性」を語る。でも「何に対する自律性か」とは問わない。ダイアルを見事に最適化したとしても、ユーザーが自分で握っていたかった判断をAIに任せてしまう。マップがなければ、間違った瞬間に向けて設計することになる。

2. 暗黙のダイアルと明示的なダイアルを混同する

低リスクで可逆なもの（レコメンデーション）は暗黙で機能する。高リスクで不可逆なもの（購入、送信）には明示的な設定が要る。区別を入れないと、「聞かずに勝手にやられた」か「どうでもいいことをいちいち聞いてくる」のどちらかになる。

3. 例外時にダイアルがリセットされない

在庫切れ、価格変動、想定外の事態。本来なら、AIは一時的に確認モードへ下がるべきだ。代替モードが設計されていないと、例外が通常時と同じ自律性で処理されてしまう。それで信頼が壊れる。

AIプロダクトを設計しているなら

チームに、三つの問いを投げかけてほしい。

問い1：ユーザーが自分で握っていたいものは何か。

→ それが「所有」の列だ。そこにAIを置いてはいけない。

問い2：このダイアルは暗黙で上昇させるべきか、ユーザーが明示的に設定すべきか。

→ リスクと可逆性で見極める。

問い3：信頼が積み上がったとき、ダイアルはどう反応するか。

→ 成功でダイアルが上がる仕組みと、失敗で下がる仕組みを、両方とも設計する。

一本の線

自律マップ = 境界線をどこに引くか

自律ダイアル = 委譲の中でどこまで
→ 暗黙（観察された行動）
→ 明示的（ユーザーが設定）

開示ダイアル = AIにどこまで知らせるか
→ 自律ダイアルの前提条件
→ 領域ごと、人ごとに異なる

代替モード = アイテムごとの例外処理

信頼 = 四つすべてを時間とともに動かすエンジン

マップなしにダイアルを回すな。
暗黙と明示的を混同するな。
例外をフル自律で実行させるな。
獲得された信頼なしに何も動かすな。
そして忘れるな：好みは変わる。

1年後、冷蔵庫は常にストックされている。あなたは何もしていない。

もし棚に見慣れないブランドが置かれていたら、それはAIの仕業だ。気に入らなければ、そう伝えればいい。ルールが少し賢くなる。

それが人間とAIの関係のかたちだ。命令でも服従でもなく、育てることだ。
