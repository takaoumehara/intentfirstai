Context Grammar — Floor 3

Brain

記憶には構造がある。フラットなリストではなく、更新速度の異なる3つの層として。そして家庭には 5 つの Brain がある。

Context Brain

覚えているレストラン

行きつけのレストランに入る。店長はもう名前を知っている。席の好みも。ナッツアレルギーも。これが Layer 1 — 変わらない土台。

ウェイターは金曜はビール派だと覚えている。疲れた日は軽めを頼むことも。魚にはいつもレモンを追加することも。これが Layer 2 — 繰り返しから積み上がるパターン。

そして今夜、上司と来ていることが見える。スーツを着ている。少し緊張している。これが Layer 3 — 今この瞬間。

3つの異なる「知り方」。3つの異なる更新速度。ひとつのシームレスな体験。

今のAIにはこの構造がない。 Claude、Gemini、ChatGPT の記憶はフラットなメモ帳 — 階層も更新サイクルもアーキテクチャもない事実の羅列。Context Brain はそこに構造を与える。

レストランに例えると

予約台帳にはアレルギーと記念日が書いてある — 最初の来店時に一度書けば、毎回参照されるがほぼ変わらない。これが Layer 1 — Identity。

ウェイターの記憶は繰り返しで育つ — 金曜はビール、疲れた日は軽め。これが Layer 2 — Learning。

今夜の観察— どんな歩き方で入ってきたか、誰と来たか、表情はどうか。これが Layer 3 — Right Now。

普遍的な解剖学

どの Brain も、3 つの Layer を持っている

Person Brain も Finance Brain も Household Brain も Event Brain も — すべて同じ 3 層構造を持つ。これが記憶の普遍的な解剖学。

アーキテクチャ

家庭には 5 つの Home Brain がある

1 つの Brain は 1 人分の記憶を持つ。家庭には 5 つ — それぞれ独立した役割を持ち、同じ 3 Layer 解剖学を持つ。

核心ルール

Layer = 普遍的な記憶解剖学。すべての Brain に存在する。Brain = 3 層を所有する 1 つの記憶主体。個人 = 1 Brain、家庭 = 5 Brain、企業 = 多数の Brain（分散認知）。正しい姿は「N 個の Brain × それぞれ 3 Layer」であり、「1 Brain × 3 Layer」ではない。

まず根っこから

Brain は「記憶」、
Agent は「行動者」、
Coordinator は「司令塔」。

「Finance Brain」と「Finance Agent」を同じものと混同する人が多い。実は全く別のものです — 図書館の本と司書ぐらい違います。3 種類のノードが協調してはじめて agentic OS が成立します。

Brain
記憶

情報をしまっておく場所。自分からは何もしない。読まれたら出す、書かれたら覚える。それだけ。

  • 家族のアレルギーを覚えている
  • 11 ヶ月分の月曜パターンを蓄える
  • 誰がアクセスできるかルールを持つ
  • 「忘れない」のが仕事
Agent
行動者

人と話す、判断する、行動する AI。Brain から情報を読んで決める。学んだら Brain に書き戻す。

  • 「これ買っていい？」と人に答える
  • Amazon でシューズを注文する
  • 通知を送る、メールを書く
  • 「動く」のが仕事
Coordinator
司令塔

複数の Brain を読み合わせて、どの Agent に何をやらせるかを判断する役。家庭サイズなら 1 つで十分。

  • 5 つの Brain を同時に参照する
  • 競合する要望の優先度を決める
  • Agent にコマンドを発行する
  • 「読み合わせて判断する」のが仕事

覚え方

Brain は名詞（記憶という物）。Agent は動詞（記憶を使って動く者）。Coordinator は指揮者（誰が読み、誰が動くかを決める者）。

レストランに例えると

レシピブック、お客様カルテ、在庫表 — これらが Brain（別々の本、それぞれ 1 つのドメインの記憶を持つ）。シェフ、ホール、ソムリエが Agent（本を読んで動く人）。どの本を誰が開き、誰が何をするかを決めるマネージャーが Coordinator。レシピブックは料理しません。シェフが本を読んで料理を作ります。

実例

Sota の靴 $48 を買う — 5 つの Brain が同時に動く

日常の何気ない一言。11 歳の男の子の発言でどれほどの記憶が動員されるかを追ってみましょう。

「お母さん、サッカーシューズきつい！」

Sota（11歳・サッカー部）· ある火曜の朝

1 Sota が話す Voice Agent
Sota は朝食で母 Mai に言う。Voice Agent が会話を聞き取り、"shoes too tight" という事実を Coordinator に伝える。
2 Coordinator が考える — 5 つの Brain を読みに行く Coordinator
Coordinator は「Sota のシューズを今すぐ買うべきか？」を判断するため、5 つの Brain を読みに行く。1 秒もかからない。

Brains が answers を返す

  • Person Brain (Sota) 11 歳・soccer Tuesday 必須・今の足サイズ EU 36（最近 5mm 伸びた）
  • Finance Brain 今月の予算残り $230・「子供必需品」枠 $150 残り・$50 以下なら自動承認 OK
  • Education Brain School dress code OK · PE class で必要
  • Calendar Brain 来週土曜に試合あり・急ぎ

→ 結論: SILENT BUY（auto-approve、ログのみ記録）
3 Shopping Agent が買う Agent
Coordinator が Shopping Agent に指示。Sota のサッカーチームが指定するブランド + 適切なサイズで Amazon に注文する。$48 + 即日配送 = 完了。
4 Brain たちが学ぶ — 結果を書き戻す Brains
行動が完了したら、Agent は学んだことを Brain に書き戻す。
  • Finance Brain$48 子供必需品費を記録、月次予算に反映（Learning Layer）
  • Person Brain (Sota)足サイズ EU 36 を Identity Layer に書き換え
  • Household Brain「silent buy」ルールが正しく機能した、と Learning Layer に記録
5 Mai の iPhone に「報告」が出る Result
Mai は何も判断しなくていい。事後報告だけ。
"Sota's soccer shoes ordered. Auto-approved. $48. — Tap to undo."

これが Silent Resolution の正体。Mai が朝の決断地獄から解放される。

「既存 AI に記憶あるじゃん」と何が違うのか

Gemini も、Apple Intelligence も、Claude も、記憶を持っています。家族のアレルギー、ルーティン、好みは覚えている。違うのは — どれも「今この瞬間」を読まない。記憶は素材。判断は素材 × Now の積で初めて成立する。これが Context Grammar の Brain アーキテクチャが言っていること。

5 階層は不変、N が変わるだけ。家族の Domain は 5、大企業の Function は 12。でも「専門知識を持つ脳が並列に存在する」構造は同じ。

よくある質問を整理する

よくある質問を整理する

Brain と Agent と Coordinator の関係性、5 つの Home Brain、3 Layer 解剖学 — 毎回出てくる 6 つの疑問。

Q1. Brain と Agent は名前を同じにしないとダメ？

いいえ。「Finance Brain」と「Finance Agent」は分かりやすさのために名前を揃えていますが、別物です。1 つの Finance Brain を Shopping Agent / Tax Agent / Budget Agent の 3 つが共有してもいい。逆に、1 つの Calendar Agent が Finance / Education / Health / Calendar / Household の 5 つの Brain を読むこともある。

Q2. Brain だけあれば AI は動かないの？

動きません。 Brain は本棚と同じ。中身を読む人（Agent）と、誰が何を読むかを決める人（Coordinator）がいないと意味がない。一方、Agent だけだと記憶が共有できない（毎回同じ説明を求められる）。3 つとも必要。

Q3. Agent が直接 Brain を書き換えていいの？

はい、ただし権限がある範囲で。 Disclosure Dial / Disclosure Matrix が、どの Agent がどの Brain にどこまで書き込めるかを決める。Finance Agent は Finance Brain にフルアクセスだけど、Person Brain には書き込めない（プライバシーの境界）。これが Project 01 で説明した 5 × 5 = 25 のアクセスルールの意味。

Q4. Coordinator は 1 つだけ？複数あってもいい？

家庭サイズなら1 つで十分。大企業になると Coordinator のヒエラルキーが必要（部門長 Coordinator → 全社 Coordinator など）。基本的には「読み合わせて判断する役」が 1 つ以上あればいい。

Q5. これって既存の AI と何が違うの？

ChatGPT / Claude は Agent だけのモデル（記憶を内部に閉じこめている）。Apple Intelligence / Samsung Family Hub は少しの Brain + 専用 Agentのモデル（家族プロファイルなど）。
Context Grammar が提案するのは分散した複数の Brain × 別レイヤーの専門 Agent × Coordinator という 3 層構造。これが "agentic OS" の正体。

Q6. 3 Layer はどの Brain にも本当に存在するの？

はい、必ず存在します。 Person Brain (Sota) には「11 歳・soccer」(Identity)・「最近背が伸びた」(Learning)・「今朝シューズきつい」(Now)。Finance Brain には「通貨 USD」(Identity)・「今月は外食多め」(Learning)・「残高 $230」(Now)。Event Brain (Kyoto Trip) ですら「日程・家族構成」(Identity)・「Kai はラーメン好き」(Learning)・「今は京都駅にいる」(Now) を持つ。Layer は普遍的な記憶解剖学です。

記憶に信頼の制御がなければ、それは監視。

Context Brain は記憶アーキテクチャ。Trust Design はコントロール層。ふたつが揃って、AI があなたの代理として動ける。
