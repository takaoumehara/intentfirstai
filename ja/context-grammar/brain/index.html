Context Grammar — Floor 3

Brain

記憶には構造がある。フラットなリストではなく、3つのLayerがある。そして一つの家には5つのBrainがある。これがAIの記憶の仕組みだ。

Context Brain

あなたを覚えているレストラン

行きつけのレストランに入ると、オーナーはすでに名前を知っている。好きな席も、ナッツアレルギーも。これがLayer 1 — 変わらない土台だ。

ウェイターは金曜日にビールを注文することを覚えている。疲れているときは軽めの料理を求めること、魚には必ずレモンを添えること。これがLayer 2 — 繰り返しから生まれるパターンだ。

今夜、上司と一緒に来た。スーツを着ている。どこかぎこちない。これがLayer 3 — 今この瞬間に起きていることだ。

3種類の「知ること」。3つの更新速度。一つのシームレスな体験。

現在のAIにはこの構造がない。 Claude、Gemini、ChatGPT — どれもメモリはフラットなノートだ。レイヤーも更新サイクルも構造もない、事実のリスト。Context Brainはそこに構造を与える。

レストランに例えると

予約台帳にはアレルギーと記念日が書いてある — 一度記入されたら、ほとんど変わらない。これがLayer 1 — Identity Layer（同一性レイヤー）だ。

ウェイターの記憶は繰り返しから育つ — 金曜はビール、疲れているときは軽めの料理。これがLayer 2 — Learning Layer（学習レイヤー）だ。

今夜の観察 — 歩き方、連れ、表情 — これがLayer 3 — Now Layer（今レイヤー）だ。

普遍的な構造

すべてのBrainは3つのLayerを持つ

Person Brain、Finance Brain、Household Brain、Event Brain — すべて同じ3層構造を共有する。これが記憶の普遍的な解剖学だ。

Layer 01 · Identity · すべてのBrainに存在

月・年単位

Identity Layer（同一性レイヤー） — このBrainの素性

属性、家族構成、食事制限、言語、アクセシビリティ — 一日の質感ではなく、人生の輪郭を定める土台。Domain Brainにとってはそのドメインの不変ルールであり、Brand Brainにとっては判断のDNAだ。

Layer 01 · Identity · すべてのBrainに存在 Identity Layer — 変わらない土台 月・年単位

Person Brainでは：属性、家族構成、食事制限、言語。Domain Brainでは：そのドメインの不変ルール。「このBrainが何者か」を決めるのがここだ。

保持する情報 Person Brain → 家族構成、食事制限、言語、アクセシビリティ
Finance Brain → 通貨、税ルール、口座構造
Household Brain → 家のルール、共有資産
情報源 ユーザーの明示的な入力 + オンボーディング + 公式設定
更新速度 月・年単位 — ライフイベント時に更新

レストランに例えると

「ナッツアレルギー。窓側の席。子ども2人。3月に記念日。」

予約台帳。初回来店時に一度書かれ、毎回の食事前に参照される — もう誰も聞かなくていい。

Key Insight

このLayerの厚みは Disclosure Dial が制御する。完全開示ならシステムは完全なIdentityを持つ。非公開モードなら名前だけ。Person BrainごとにもDomain Brainごとにも、異なる開示レベルを設定できる。決めるのはユーザーだ。

Layer 02 · Learning · すべてのBrainに存在

日・週単位

Learning Layer（学習レイヤー） — 積み重なるもの

信頼を積み上げる — あるいは失う — Layerだ。各Brainは自分のドメインで独自の学習を蓄積する。Person Brainは行動パターンを、Finance Brainは支出傾向を、Calendar Brainは曜日ごとのスケジュール密度を学ぶ。

Layer 02 · Learning · すべてのBrainに存在 Learning Layer — 繰り返しから生まれるパターン 日・週単位

生の事実からスタートし、文脈的な理解へと育つ。システムは観察し、相関を見つけ、行動モデルを構築する — やりとりのたびに精度が上がり、修正に応じて軌道を修正する。

保持する情報 Person Brain → 食の好み、買い物の習慣、コミュニケーションスタイル
Finance Brain → 月次の支出パターン、カテゴリ別しきい値
Calendar Brain → 曜日ごとのスケジュール密度
情報源 行動からの暗黙的な学習 + ユーザーの修正フィードバック
進化の流れ 来店1回目：サーモンを注文した（事実）
来店3回目：たぶんサーモンが好き（パターン）
来店10回目：金曜は疲れていて軽めの料理＋ビールを求める（文脈的）
来店20回目：妻がいるときはワイン、一人ならビール（関係性）

レストランに例えると

20回担当したウェイターは、金曜はビール、奥さんが来るとワインを注文することを知っている。何も書き留めていない — 繰り返しから育ち、修正によって磨かれた記憶だ。ときに間違うが、確実に良くなっていく。

Key Insight

Learning Layerは誤ったパターンを学ぶこともある。サーモンを3回注文した — でも実はゲスト用だった。修正フィードバックが軌道を修正する。誤りが続くとAutonomy Dialが自動でレベルを下げ、確信を減らして確認を増やすようになる。

Layer 03 · Now · すべてのBrainに存在

秒・分単位

Now Layer（今レイヤー） — 今この瞬間に起きていること

最も速いLayerだ。呼吸するLayerとも言える。リアルタイムのToken値、アクティブなIntent、デバイスの状態。コンテキストが切り替わるたび、センサーが読み取るたび、新しい情報が入るたびに変化する。Finance Brain（現在の残高）、Calendar Brain（今日のスケジュール密度）、Event Brain（現在地：京都）— すべてのBrainにこのLayerが存在する。

Layer 03 · Now · すべてのBrainに存在 Now Layer — リアルタイムフィード 秒・分単位

最も速いLayerだ。現在のToken値、アクティブなIntent、デバイスの状態 — 新しい情報が入るたびに秒単位で書き換えられる。

情報源 センサーデータ + アクティブセッションのコンテキスト
更新速度 秒・分単位

ウェイターは空気を読む — ペース、表情、連れ。履歴は不要。ただ今、目を開けているだけでいい。

アーキテクチャ

5つのHome Brain

1つのBrainは1人の記憶を持つ。家には5つある — それぞれ固有の役割を持ちながら、同じ3層構造を共有している。

Brain 01
Household Brain
家のルール、共有資産、判断のDNA。「子ども向け必需品が5,000円以下 → サイレント購入」。永続する土台。
Brain 02
Person Brain × 5
家族それぞれの個別メモリ。マイ / レン / ソウタ / ミオ / おじいちゃん — 互いに独立している。
Brain 03
Domain Brain × N
ドメイン別の専門知識。家計 / 教育 / 健康 / カレンダー — 一家族で約5つのDomain Brainが並列稼働する。
Brain 04
Household Coordinator
指揮者。すべてのBrainを横断的に読み、どのAgentが動くかを決める。Coordinatorノードであり、Brainではない — 自身のメモリは持たない。
Brain 05
Event Brain × N
期間限定の目的のために生まれる。京都旅行 / 引越し / 受験 — 目的が終わると消滅する。学習だけがHome Brainに戻る。

基本ルール

Layer = 普遍的な記憶の解剖学。すべてのBrainに存在する。Brain = 3つのLayerを持つ記憶エンティティ。個人 = 1 Brain。家族 = 5 Brains。企業 = 多数のBrains（分散認知）。正しいフレーミングは「N個のBrain × それぞれ3つのLayer」— 「1 Brain × 3 Layer」ではない。

基本構造

Brainはメモリだ。
Agentはアクションだ。
Coordinatorは指揮者だ。

「Finance Brain」と「Finance Agent」を混同する人は多い。この2つはまったく別物だ — 図書館と司書ほどの違いがある。エージェンティックOSを実現するには、3種類のノードが連携して動く。

Brain
メモリ

情報を保持する場所。それ自体では何もしない。読めば答え、書けば覚える。それだけが仕事だ。

  • 家族のアレルギーを覚えている
  • 11ヶ月分の月曜日のパターンを蓄積する
  • 誰が何にアクセスできるかのルールを保持する
  • 「忘れないこと」が仕事だ
Agent
実行者

人と対話し、判断し、行動するAI。Brainから読んで判断し、学んだことを書き戻す。

  • 「これを買うべきか？」に答える
  • Amazonで靴を注文する
  • 通知を送り、メールを書く
  • 「動くこと」が仕事だ
Coordinator
指揮者

複数のBrainを同時に読み、どのAgentが何をするかを決める。家庭規模では1つのCoordinatorで十分だ。

  • 5つのBrainを同時に参照する
  • 競合する優先度を解決する
  • Agentに指示を出す
  • 「横断的に読んで決める」のが仕事だ

覚え方

Brainは名詞 — もの（記憶）だ。Agentは動詞 — 記憶を使って動く存在だ。Coordinatorは指揮者 — 誰が何を読んで誰が動くかを決める存在だ。

レストランに例えると

レシピブック、顧客台帳、在庫リスト — これらがBrainだ（それぞれ1ドメインの記憶を持つ別々の本）。シェフ、フロアマネージャー、ソムリエがAgentだ（本を読んで行動する）。誰がどの本を開いて何をするかを決めるゼネラルマネージャーがCoordinatorだ。レシピブックは料理しない。シェフがそれを読んで料理する。

1つのAI、4つのルールセット

同じCoordinator、同じHousehold Brain — でも各Person BrainはそれぞれのAutonomy Dial設定とSubstitution Modeを持つ。1つのAIが4人に同時に、それぞれの条件でサービスを提供する。

1つのBrain、4つの並列状態

Coordinatorは各Person Brainを独立して読む。ルールが衝突したとき — ママが指定のヨーグルトを求めているが在庫切れの場合 — 誰の好みが優先するかを知っている。

実例

ソウタの靴5,000円 — 5つのBrainが一斉に動く

ごく日常的な家族のひとコマ。11歳の一言が、どれだけの記憶を動かすか追ってみよう。

「ママ、サッカーのシューズがきつくなった！」

ソウタ、11歳 · サッカー部 · 火曜の朝

1 ソウタが話す Voice Agent
朝食時に発言。Voice Agentが会話を聞いて、「シューズがきつい」をCoordinatorに渡す。
2 Coordinatorが5つのBrainを読む — 1秒以内に Coordinator
Coordinatorは「ソウタのシューズを今注文すべきか？」に答えるために、5つのBrainを同時に読む。

各Brainからの回答

  • Person Brain（ソウタ） 11歳 · 火曜サッカー必須 · 現在の足のサイズEU 36（最近5mm成長）
  • Finance Brain 今月の残り予算23,000円 · 「子ども必需品」枠15,000円残 · 5,000円以下 = 自動承認
  • Education Brain 学校の服装規定OK · 体育の授業にスポーツシューズ必須
  • Calendar Brain 次の土曜に試合 · 緊急
  • Household Brain 家のルール：「子ども必需品5,000円以下 → サイレント購入、ログのみ」
→ 判定：SILENT BUY（自動承認、ログのみ）
3 Shopping Agentが注文する Agent
CoordinatorがShopping Agentに指示。Shopping Agentがチーム指定ブランドの正しいサイズをAmazonで注文する。4,800円 + 当日配達 = 完了。
4 Brainが学ぶ — Agentが書き戻す Brains
アクション完了後、Agentが学んだことを関連するBrainに書き戻す。
  • Finance Brain子ども必需品4,800円の支出を記録、月次予算を更新（Learning Layer）
  • Person Brain（ソウタ）Identity LayerでEU 36に足のサイズを更新
  • Household Brain「サイレント購入」ルールが正しく発動したことを記録 — Learning Layer
5 マイがiPhoneでレポートを見る 完了
マイは何も決断しない。受け取るのは事後レポートだけだ。
「ソウタのサッカーシューズを注文しました。自動承認。4,800円。— タップで取消し」

これがSilent Resolution（サイレント解決）だ。マイは朝の決断ラッシュから解放される。

何が起きたか

ソウタの一言が5つのBrain、1つのCoordinator、3つのAgent（Voice / Shopping / Notification）を動かした。誰もプログラミングの知識は不要だった。家族は普通に話しただけだ。

Brain ↔ Agent — 一対一ではない

1つのBrainは複数のAgentから読まれる。1つのAgentは複数のBrainを読める。これが正しいモデルだ。

同時に起きている3つのパターン

① 1つのBrain（Person Brain）が複数のAgentに読まれる
② 1つのCoordinatorが複数のBrainを読む
③ AgentはBrainに書き戻す（メモリ更新）

ライフサイクル

Disposable Brain

目的のために生まれ、目的が終われば消える。学びだけが残る。

すべてが永続する必要はない。京都への家族旅行は、AIの記憶に永遠に場所を占める必要はない。でも旅行から得た学びは — それは残るべきだ。

Event Brainは明確なライフサイクルを持つ期間限定の記憶インスタンスだ。他のBrainと同じ3層構造を持つ。Project 02: The Family Tripで実際の適用例を見る →

Concept · Trip Brain Lifecycle 4フェーズ：誕生（Identity Layerを継承）、学習（3層すべてが充填）、帰還（知識がHome Brainへ流入）、消滅（コンテナ消失、記憶は永続）。

01

誕生

Trip Brainは5つのHome Brainから引き継ぐ：家族のアレルギー、好み、過去の旅行パターン。ブランクではなく、最初から情報を持った状態で生まれる。

02

学習

旅行中に独自のLearning Layerを構築する。「カイがラーメンを気に入った」「ミアは午後3時に眠くなる」。このコンテキストにしか存在しない洞察。

03

帰還

価値ある学びがHome Brainに戻る。「カイはラーメンが好き」がPerson Brain（カイ）のLearning Layerに永続的に残る。

04

消滅

Event BrainとそのUIは消える。プランは使い捨てだ。記憶は永続する。コンテキストは終わるが、知恵は残る。

レストランに例えると

誕生日パーティーには特別なプランがある：飾り付け、特注メニュー、増員スタッフ。終わったら飾りを片付ける。でも「このゲストがパーティーを開いた」という記録は予約台帳に残る。翌年また予約が入ったとき、前年の体験がより良いプランを生む。

旅行に限らない — 期間限定の目的ならすべて

期間限定の目的があればEvent Brainを生み出せる。目的が終われば消滅する — ただし学びはHome Brainに戻る。

酸素

記憶は凍っている。
"Now Layer"がそれを溶かす。

Now Layerが流れ込むまで、Identity LayerとLearning Layerは静的なデータだ。「今」が届いた瞬間、知識が生きてアクションが可能になる。この原則はすべてのBrainに適用される — 5つすべてに。

Before — データだけ

Identity + Learning

「卵アレルギー」（Person Brain · Identity）+「金曜は疲れている」（Person Brain · Learning）= ただのデータ。AIはこれだけでは動けない。

After — + Now Layer

Identity + Learning + Now

+「火曜18:30、妻がキッチンにいる、冷蔵庫にパスタとブロッコリー、夕食まで25分」（Person Brain · Now）

=「卵なしのパスタ、20分、冷蔵庫の食材で。進めますか？」

記憶は原材料だ。「今」と交差して初めて、判断になる。

レストランに例えると

予約台帳を眺めているだけでは料理は出てこない。今夜のゲストがどんな歩き方で入ってきたか — ペース、表情、連れ — を見た瞬間、サービスが動き出す。

既存のAIのメモリとの違いは何か？

Gemini、Apple Intelligence、Claude — どれもアレルギー、ルーティン、好みを覚えている。違いは：その記憶をこの瞬間に使っていない。記憶は原材料だ。記憶が「今」と交差して初めて判断が生まれる。Context Brainアーキテクチャが実現するのはそこで — フラットなメモリリストにはできないことだ。

スケールモデル

5つの階層。どんな規模にも対応する。

個人から家族、企業まで — 同じ5つの階層がすべてのケースを説明する。変わるのはNの値だけ。Layerは常に3つ。Brainの階層は常に5つだ。

重要なポイント

5つの階層は不変 — 変わるのはNの値だ。家族には5つのDomain Brainがある。企業には12のFunction Brainがある。でも「並列Brainに分散する専門知識」という構造は、どの規模でも同じだ。
AgentはBrainとは別の可変レイヤーだ。スタートアップは3人のAgentが兼務で動く。企業は12人の専任Agentが動く。Layerは常に3つで固定だ。

よくある質問

よくある質問

Brain・Agent・Coordinator — 5つのHome Brain — 3層構造。毎回必ず出る6つの疑問に答える。

Q1. BrainとAgentは同じ名前でなければいけないか？

そんなことはない。「Finance Brain」と「Finance Agent」は分かりやすさのために同じ名前を使っているが、別物だ。1つのFinance Brainを3つのAgent（Shopping / Tax / Budget）が共有してもいい。逆に、1つのCalendar Agentが5つのBrain（Finance / Education / Health / Calendar / Household）を読んでもいい。これは正常であり、想定内だ。

Q2. BrainだけでAIは動くか？

動かない。Brainは本棚だ。読む人（Agent）と誰が何を読むかを決める人（Coordinator）がいなければ効果はない。逆に、Agentだけでは共有メモリがない — 毎回ゼロからスタートになる。3つすべてが必要だ。

Q3. AgentはBrainに直接書き込めるか？

書き込める — 権限の範囲内で。Disclosure DialとDisclosure Matrixが、どのAgentがどのBrainにどこまで書き込めるかを決める。Finance AgentはFinance Brainへの全アクセスを持つが、Person Brainには書き込めない（プライバシー境界）。Project 01の「5 × 5 = 25のアクセスルール」とはこれを指している。

Q4. Coordinatorは1つだけか？

家庭規模では1つで十分だ。企業規模ではCoordinatorヒエラルキーが必要になる（部門Coordinator → 全社Coordinator）。本質的な要件は、「横断的に読んで決める」役割が1つ以上存在することだ。

Q5. 既存のAIとどう違うか？

ChatGPT / ClaudeはAgentのみのモデル（メモリは内部に閉じている）。Apple Intelligence / Samsung Family Hubは一部Brain + 専用Agentのモデル（家族プロファイルなど）。
Context Grammarが提案するのは分散型マルチBrain × レイヤー分離型専門Agent × Coordinatorの3層構造だ。これが「エージェンティックOS」を実現するアーキテクチャだ。

Q6. すべてのBrainに本当に3つのLayerがあるか？

ある、必ず。Person Brain（ソウタ）：「11歳 · サッカー」（Identity）·「最近急に成長している」（Learning）·「今朝シューズがきつい」（Now）。Finance Brain：「通貨USD」（Identity）·「今月は外食が増えている」（Learning）·「残高$230」（Now）。Event Brain（京都旅行）も：「日程 · 家族人数」（Identity）·「カイがラーメンを気に入った」（Learning）·「現在地：京都駅」（Now）。Layerは普遍的な記憶の解剖学だ。

信頼の制御なきメモリは監視だ。

Context Brainは記憶のアーキテクチャ。Trust Designはその制御レイヤーだ。この2つが揃って、AIはあなたの代わりに動ける。
