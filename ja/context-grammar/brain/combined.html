Context Grammar · Concept · Brain (Combined)

Brain は、5つあって、
3つの層を持っている。

AI の「分散認知システム」は、Brain（記憶）と Agent（行動者）と Coordinator（司令塔）の3種類のノードでできている。
家庭には 5 つの Home Brain があり、そのそれぞれが 3 つの Layer を持つ — それが Context Grammar の心臓部です。

Section A

まず根っこから — Brain は「記憶」、Agent は「行動者」、Coordinator は「司令塔」

多くの人が「Finance Brain」と「Finance Agent」を同じものと混同します。実は全く別のものです。図書館の本と司書ぐらい違います。3種類のノードが一緒に動いて、はじめて agentic OS が成立します。

📚
Brain
記憶

情報をしまっておく場所。自分からは何もしない。読まれたら出す、書かれたら覚える。それだけ。

  • 家族のアレルギーを覚えている
  • 11ヶ月分の月曜パターンを蓄える
  • 誰がアクセスできるかルールを持つ
  • 「忘れない」のが仕事
🏃
Agent
行動者

人と話す、判断する、行動する AI。Brain から情報を読んで決める。学んだら Brain に書き戻す。

  • 「これ買っていい？」と人に答える
  • Amazon でシューズを注文する
  • 通知を送る、メールを書く
  • 「動く」のが仕事
🎼
Coordinator
司令塔

複数の Brain を読み合わせて、どの Agent に何をやらせるかを判断する役。家庭サイズなら1つで十分。

  • 5つの Brain を同時に参照する
  • 競合する要望の優先度を決める
  • Agent にコマンドを発行する
  • 「読み合わせて判断する」のが仕事
覚え方: Brain は名詞（記憶という物）。Agent は動詞（記憶を使って動く者）。Coordinator は指揮者（誰が読み、誰が動くかを決める者）。

レストランで考えてみる

🍽 レストランの裏側で起きていること

📚 Brain (記憶) = 書類・本・台帳

そこにあるだけ。自分から動かない。

・レシピブック
・お客様カルテ（アレルギー、好み）
・在庫表
・衛生管理マニュアル

🏃 Agent (行動者) = 動く人々

本を読んで、考えて、行動する。

・シェフ（レシピを読んで料理を作る）
・ホール係（お客様カルテを見て案内する）
・ソムリエ（在庫表を見てワインを薦める）
・マネージャー（全部見て判断する＝Coordinator）
レシピブックは何もしません。シェフが本を読んで料理を作ります。
Brain は本。Agent はシェフ。Coordinator は全部読んで誰に何をやらせるか決めるマネージャー。
Section B

家庭には 5 つの Home Brain がある

旧モデルは「1つの Context Brain × 3つの Layer」と説明していました。今のモデルでは 家庭の記憶は 5 つの Brain に分かれて並列に存在します。それぞれの Brain が独立した役割を持ち、それぞれが 同じ 3 Layer の解剖学を持っています。

Five Home Brains — Yamashiro 家の場合
Brain 01
Household Brain
家のルール・共有資産・家族としての判断 DNA。「子供必需品 $50 以下なら silent buy」のようなルール群。
Brain 02
Person Brain × 5
家族 1 人ずつの個人記憶。Mai / Ren / Sota / Mio / 祖父 — それぞれ独立。
Brain 03
Domain Brain × N
専門知識ごと。Finance / Education / Health / Calendar など、家庭でも 5 つほど並列に存在。
Brain 04
Household Coordinator
司令塔。複数の Brain を読み合わせ、どの Agent を動かすか決める。Brain ではなく Coordinator ノード。
Brain 05
Event Brain × N
時限つき。Kyoto Trip / 引越し / 受験など、目的が終われば消える。学びだけが Home Brain に戻る。
大事な区別: Brain（記憶ノード）と Agent（行動ノード）と Coordinator（司令塔ノード）は3 種類の別レイヤーです。Brain が増えても Agent は増えません。逆に、1 つの Agent が複数の Brain を読むことも、1 つの Brain を複数の Agent が共有することも普通です。
In restaurant terms

「レシピブック」「お客様カルテ」「在庫表」「衛生管理マニュアル」「予約台帳」— これらは別の本として存在します。1冊の万能ノートではありません。マネージャー（Coordinator）はその場で必要な数冊を開き、シェフやホール（Agent）に指示を出します。

Section C · 実例

Sota の靴 $48 を買う — 5 つの Brain が同時に動く

日常の何気ない判断ひとつで、家庭のどれだけの記憶が動員されているかを追ってみましょう。

「お母さん、サッカーシューズきつい！」

— Sota (11歳・サッカー部) · ある火曜の朝

1 Sota が話す Voice Agent
Sota は朝食で母 Mai に言う。
Voice Agent（音声を聞いている AI）が会話を聞き取り、"shoes too tight" という事実を Coordinator に伝える。
2 Coordinator が考える — 5つの Brain を読みに行く Coordinator
Coordinator は「Sota のシューズを今すぐ買うべきか？」を判断するため、5つの Brain を順番に読みに行く。これは1秒もかからない。
📚 Brains が answers を返す
  • Person Brain
    (Sota)     11歳・soccer Tuesday 必須・今の足サイズ EU 36（最近5mm 伸びた）
  • Finance Brain 今月の予算残り $230・"子供必需品" 枠 $150 残り・$50 以下なら自動承認 OK
  • Education Brain School dress code OK・PE class で必要
  • Calendar Brain 来週土曜に試合あり・急ぎ
  • Household Brain 家のルール: "子供の必需品 $50 以下 → silent buy OK"
→ 結論: SILENT BUY (auto-approve, ログだけ記録)
3 Shopping Agent が買う Agent
Coordinator が Shopping Agent に指示。
Shopping Agent は Sota のサッカーチームが指定するブランド + 適切なサイズで Amazon に注文する。$48 + 即日配送 = 完了。
4 Brain たちが学ぶ — 結果を書き戻す Brains
行動が完了したら、Agent は学んだことを Brain に書き戻す。
  • Finance Brain$48 子供必需品費 を記録、月次予算に反映 (Learning Layer)
  • Person Brain (Sota)足サイズ EU 36 を Identity Layer に書き換え
  • Household Brain"silent buy" ルールが正しく機能した、と Learning Layer に記録
5 Mai の iPhone に「報告」が出る Result
Mai は何も判断しなくていい。事後報告だけ。
"Sota's soccer shoes ordered. Auto-approved. $48. — Tap to undo."

これが Silent Resolution の正体。Mai が朝の決断地獄から解放される。
気づきポイント: Sota の一言で、5 つの Brain・1 つの Coordinator・3 つの Agent（Voice / Shopping / Notification）が連携した。誰一人プログラミングの知識を必要としていない。家族はただ普通に話しただけ。

Brain ↔ Agent の関係 — 1対1ではない

1つの Brain を複数の Agent が読む。1つの Agent が複数の Brain を読む。これが正しい使い方。

情報の流れ — Sota の靴を買うシーンで（アニメーション再生中）
3つのパターンが同時に起きている:
① 1つの Brain (Person Brain) を複数の Agent が読む
② 1つの Coordinator が複数の Brain を読む
③ Agent が学んだら Brain に書き戻す（記憶の更新）
Section D · 解剖学

どの Brain も、3 つの Layer を持っている

Brain（記憶ノード）の中身は、すべて同じ 3 層構造です。Person Brain も、Finance Brain も、Household Brain も、Event Brain も — Identity / Learning / Now の3層に分かれている。これが Universal Anatomy。Layer は記憶の解剖学、Brain は記憶の主体、と理解してください。

Layer 01 · Identity · in every brain
Identity Layer
予約台帳

変わらない土台。家族構成、アレルギー、職場、住所、ブランド DNA — その Brain が「何者か」を決める情報。

Months · Years

Update: 月〜年単位

Layer 02 · Learning · in every brain
Learning Layer
ウェイターの記憶

繰り返しから蓄積されるパターン。「金曜は疲れている」「ワインは妻と一緒のとき」など、行動の文脈モデル。修正で軌道が変わる。

Days · Weeks

Update: 日〜週単位

Layer 03 · Now · in every brain
Now Layer
今この瞬間の観察

8 Context Tokens の現在値、active intent、device state — 秒単位で書き換わる「今」のフィード。

Seconds · Minutes

Update: 秒〜分単位

核心ルール: Layer = 普遍的な記憶解剖学。すべての Brain に存在する。Brain = 3 層を所有する1つの記憶主体。個人 = 1 Brain、家庭 = 5 Brain、企業 = 多数の Brain（分散認知）。「1 Brain × 3 Layer」ではなく「N 個の Brain × それぞれ 3 Layer」が正しい姿です。
Layer 01 · Identity · in every brain Identity Layer — 変わらない土台 Months · Years

人の場合は人口統計・家族構成・アレルギー・言語。Domain Brain の場合はその専門領域の不変ルール。Brand Brain の場合は判断 DNA。「その Brain が何者か」を決める層。

何が入るか Person Brain → 家族構成・食事制限・言語・アクセシビリティ。Finance Brain → 通貨・課税ルール・口座構成。Household Brain → 家のルール・共有資産。
情報源 明示的なユーザー入力 + オンボーディング + 公式設定
更新速度 月〜年単位 — 人生の節目で更新される
In restaurant terms

「Mr. Umehara: nut allergy, window seat, 2 children, anniversary in March.」
予約台帳。一度書いたらほぼ変えない。来店のたびに参照される。

Key Insight

この層の厚みを決めるのが Disclosure Dial。完全公開なら詳細な人物像、最小公開なら名前だけ — どこまで AI に知らせるかをユーザーが決める。Person Brain ごと、Domain Brain ごとに異なる開示レベルを設定できる。

Layer 02 · Learning · in every brain Learning Layer — 繰り返しから蓄積するパターン Days · Weeks

信頼を獲得する層。あるいは失う層。生の事実から始まり、文脈的な理解へ進化する。各 Brain がその専門領域で固有の Learning を蓄える。

何が入るか Person Brain → 食の好み・買い物パターン・コミュニケーションスタイル。Finance Brain → 月次の支出傾向・カテゴリ別の閾値。Calendar Brain → 曜日別の混雑度。
情報源 行動の暗黙学習 + ユーザーの修正フィードバック
どう進化するか 訪問1: salmon を注文 (事実)。
訪問3: salmon が好きそう (パターン)。
訪問10: 金曜は疲れていて軽食 + ビール (文脈パターン)。
訪問20: 妻同伴ならワイン、一人ならビール (関係パターン)。
In restaurant terms

ウェイターの記憶。書き留められていない。繰り返しで作られる。修正で精度が上がる。たまに間違うが、徐々によくなる。

Key Insight

Learning Layer は間違ったパターンを学ぶこともある。「3回 salmon を注文した = 好物」と推測するが、実は接待のためだったかもしれない。修正フィードバックが軌道を直す。間違いが続けば Autonomy Dial が降格される — システムが自信を下げ、Suggest 寄りに戻る。

Layer 03 · Now · in every brain Now Layer — 秒単位で書き換わる「今」 Seconds · Minutes

最速の層。呼吸する層。リアルタイムフィード。Token 値、active intent、device state — フレームに入ってきた情報で書き換わる。

何が入るか 8 Context Tokens の現在値（Physical State / Cognitive Load / Social Exposure / Priority Weight / Form Factor / Feasibility / Autonomy Dial / Disclosure Dial）、active intent、device state
情報源 センサーデータ + active session context
更新速度 秒〜分単位
In restaurant terms

「今日は急いでる」「子供連れ」「疲れた表情」— ウェイターの今この瞬間の観察。履歴は要らない。目を開けてさえいれば見える。

Key Insight

Now Layer は 8 Context Tokens が住む場所。Physical State、Cognitive Load、Social Exposure、Priority Weight、Form Factor、Feasibility、Autonomy Dial、Disclosure Dial — すべての Token が現在値をこの層に流し込んでいる。これがリアルタイムの脈拍。

Section E · ライフサイクル

Disposable Brain — 目的のために生まれ、終わったら消える

すべての記憶を永続させる必要はありません。Kyoto への家族旅行のために、AI の記憶に永久の棚を割り当てる必要はない。でもその旅で学んだことは残すべきです。Event Brain は、目的を持って生まれ、終わったら溶けて消える時限つきの Brain。それでも他の Brain と同じ 3 Layer 解剖学を持っています。

01 · Birth
誕生
Trip Brain は Home Brain（5つ）から必要なものを継承して生まれる。家族のアレルギー、子供の好み、過去の旅行パターン — 真っ白ではなく、プリロード済み。
02 · Learn
学習
旅の中で固有の知識を Learning Layer に積む。「Kai がラーメンに目覚めた」「Mia は午後3時にぐずる」— この文脈の中だけで意味を持つ洞察。
03 · Return
帰宅
価値ある学びは Home Brain に流れ戻る。「Kai はラーメン好き」が Person Brain (Kai) の Learning Layer に永続化される。
04 · Dissolve
解散
Trip Brain と専用 UI は消える。プランは使い捨て、記憶は永続。文脈は終わるが、知恵は残る。
In restaurant terms

誕生日パーティには専用プランが立つ — 装飾、特別メニュー、追加スタッフ。終われば装飾は片付ける。でも「このゲストはうちでパーティを開いた」という記録は予約台帳に残る。来年予約が入ったとき、去年の経験がより良いプランを生む。

旅行だけじゃない — Event Brain の例

時限つきの目的なら、Event Brain がスポーンする。目的が終われば溶ける。学びは Home Brain に戻る。

Event Brain パラメータ (Identity Layer) 学ぶこと (Learning Layer)
Kyoto Trip 日程、家族人数、予算、食事制限 子供のスタミナパターン、好む料理ジャンル
Moving House 新住所、引越し日、間取り 部屋の使い方、近所のルーティン
Hurricane Response 警報レベル、避難ゾーン、備蓄状態 避難判断の基準、家族の集合パターン
Product Launch 締切、チーム、成果物 ボトルネックパターン、理想的な会議時間
娘の受験 試験日、志望校、科目 集中時間帯、ストレスシグナル
Section F · 酸素

記憶は凍っている。「Now Layer」が解凍する。

Now Layer (L3) が流れ込むまで、Identity Layer (L1) と Learning Layer (L2) は静的なデータに過ぎません。「今」が到着した瞬間、知識が生き物になり、行動が可能になります。これは 5 つの Brain すべてに当てはまる原理です。

Before — data only

Identity + Learning だけ

「卵アレルギー」(Person Brain · Identity) +「金曜は疲れている」(Person Brain · Learning) = ただのデータ。AI はこれだけでは動けない。

After — + Now Layer

Identity + Learning + Now

+「火曜 18:30、妻はキッチン、冷蔵庫にパスタとブロッコリー、夕食まで25分」(Person Brain · Now)

= 「卵抜きパスタ、20分、冷蔵庫の食材で。進めますか？」
記憶は素材。判断になるのは、「今」と交差したときだけ。
In restaurant terms

予約台帳をいくら見つめても料理はできない。スタッフが「今夜どんな歩き方で入ってきたか」— ペース、表情、同伴者 — を見た瞬間、サービスが生き物になる。

「既存 AI に記憶あるじゃん」と何が違うのか

Gemini も、Apple Intelligence も、Claude も、記憶を持っています。家族のアレルギー、ルーティン、好みは覚えている。違うのは — どれも「今この瞬間」を読まない。記憶は素材。判断は素材 × Now の積で初めて成立する。これが Context Grammar の Brain アーキテクチャが言っていることです。

Section G · ベースモデル

どんな規模でも通用する 5 階層

1人の個人から、家族、スタートアップ、大企業まで — 同じ 5 階層で記述できる。違うのは「N の数字」だけ。Layer は 3、Brain の Tier は 5。

Tier 役割 個人 (1人) 家族 (5人) スタートアップ (30人) 大企業 (1000+)
1 永続土台 Self Brain Household Brain Org Brain Org Brain
2 判断 DNA — Person × 5 Person × 30 / Brand × 1 Brand × N（多商品・地域別）
3 専門知識 Health / Money / Schedule (3) Domain × 5（Finance / Edu / Health / Cal / Home） Function × 3-4（Ops / Customer / Finance） Function × 8-12（Legal / HR / Finance / Marketing / Sales / Eng / Customer / Research / Ops…）
4 司令塔 (自分の脳) Household Coordinator PMB PMB hierarchy
5 時限実行 Trip / Move Event × N Project × few Project × many
キーポイント: 5 階層は不変、N が変わるだけ。家族の Domain は 5、大企業の Function は 12。でも「専門知識を持つ脳が並列に存在する」構造は同じ。
Agent は別レイヤーで可変。スタートアップは 3 Agent で兼任、大企業は 12 Agent に分業。Layer は 3 で固定。

よくある質問を整理する

Q1. Brain と Agent は名前を同じにしないとダメ？
いいえ。 「Finance Brain」と「Finance Agent」は分かりやすさのため名前を揃えてるけど、別物。1つの Finance Brain を Shopping Agent / Tax Agent / Budget Agent の3つが共有してもいい。逆に、Calendar Agent 1つが Finance / Education / Health / Calendar / Household の 5 つの Brain を読むこともある。
Q2. Brain だけあれば AI は動かないの？
動きません。 Brain は本棚と同じ。中身を読む人（Agent）と、誰が何を読むかを決める人（Coordinator）がいないと意味がない。一方、Agent だけだと記憶が共有できない（毎回同じ説明を求められる）。3つとも必要。
Q3. Agent が直接 Brain を書き換えていいの？
はい、ただし権限がある範囲で。 Disclosure Dial / Disclosure Matrix が、どの Agent がどの Brain にどこまで書き込めるかを決める。Finance Agent は Finance Brain にフルアクセスだけど、Person Brain には書き込めない（プライバシーの境界）。これが Project 01 で説明した 5 × 5 = 25 のアクセスルールの意味。
Q4. Coordinator は1つだけ？複数あってもいい？
家庭サイズなら1つで十分。大企業になると Coordinator のヒエラルキーが必要（部門長 Coordinator → 全社 Coordinator など）。基本的には「読み合わせて判断する役」が1つ以上あればいい。
Q5. これって既存の AI と何が違うの？
ChatGPT / Claude は Agent だけのモデル（記憶を内部に閉じこめている）。Apple Intelligence / Samsung Family Hub は少しの Brain + 専用 Agentのモデル（家族プロファイルなど）。
Context Grammar が提案するのは分散した複数の Brain × 別レイヤーの専門 Agent × Coordinator という3層構造。これが "agentic OS" の正体。
Q6. 3 Layer はどの Brain にも本当に存在するの？
はい、必ず存在します。 Person Brain (Sota) には「11歳・soccer」(Identity)・「最近背が伸びた」(Learning)・「今朝シューズきつい」(Now)。Finance Brain には「通貨 USD」(Identity)・「今月は外食多め」(Learning)・「残高 $230」(Now)。Event Brain (Kyoto Trip) ですら「日程・家族構成」(Identity)・「Kai はラーメン好き」(Learning)・「今は京都駅にいる」(Now) を持つ。Layer は普遍的な記憶解剖学です。
