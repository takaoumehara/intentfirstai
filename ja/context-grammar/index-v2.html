Context Grammar

あなたを知っている行きつけのレストラン

毎週金曜日に通うレストランがある。ホストはあなたの名前を覚えている。ウェイターは先週の注文を覚えていて、今日も同じものが来ると分かっている。でも今夜、上司を連れてきた — ウェイターは空気を読んで、ワインの提案を省いた。

三種類の「知り方」。三つの異なる更新スピード。一つのシームレスな体験。スクリプトもチェックリストも必要ない。記憶、パターン、観察が協調して動いている。

Agentic AIにも、この構造が必要だ。Context Grammarは、その部品に名前をつける。デザイナーとエンジニアが一貫して構築できるように。

レストランに例えると

行きつけのレストランに入ったとき、ホストはあなたの名前を知っている。ウェイターはいつものオーダーを覚えている。今夜は上司を連れてきたと気づく — 三つの「知り方」、三つの更新スピード、一つのシームレスな体験。それがContext GrammarのAIへの贈りもの。

Framework Overview

フレームワーク全体を60秒で

Context Grammarは三つの中核レイヤーと四つのサポート要素で構成される。合わせると、Agentic Systemが人を理解し、正しく応答するために必要なすべてを記述できる。

How They Connect

1つのシグナルが6回変換される

実際のインタラクションは6つの要素を通過する。Intentとして入力され、Tokenが状況を記述し、Brainが記憶を提供し、Rule Engineが衝突を解消し、AX Patternがインターフェースを形成し、Specsが移植可能にする。

01
Intentが入力される

明示的：「ピザを注文して」。暗黙的：カレンダーの密度と低エネルギーシグナルから「夕食を素早く解決したい」と推論。Intentは目的地 — 残りの要素はそこへのナビゲーションを担う。

02
8 Tokenが状況を記録する

Physical State（疲れている、21:30、自宅）、Cognitive Load（高 — 今日は3回の会議）、Social Exposure（一人）、Feasibility（Deliverooは営業中、支払い確認済み）。6つの状況Tokenが今の現実を記述する。

03
Brainが記憶を提供する

Identity Layer：グルテンアレルギー、お気に入りの2軒。Learning Layer：金曜日は和食、デリバリー最低注文額が嫌い。Now Layer：現在のToken値がリアルタイムのカレンダーと位置情報とマージされる。

04
Rule Engineがデザインルールを出力する

Autonomy DialはConfirmに設定。Cognitive Loadが高い。ルール：40店舗のリストを表示しない — 1つを事前選択し、確認を1タップで済ませる。「ユーザーは選びたい」対「今夜は選ぶ余裕がない」の衝突をここで解消する。

05
AX Patternがインターフェースを形成する

Pattern A3 — Confident Suggestion — が発火。1枚のカード、1タップで確認。ナビゲーションも検索もメニュー閲覧も不要。Ruleがすでに決定を下した。UIはそれを確認するだけ。

06
Specsが移植可能にする

このインタラクションのYAMLスキーマ — Token値、Brain状態、ルール出力、AX PatternのID — はあらゆるサーフェスに渡せる：スマートフォン、テレビ、冷蔵庫、CarPlay。同じIntent、適応された形。

Floor 3 · Brain

5種類のBrain、それぞれに3つのLayer

一つの家庭は一つの心ではない。冷蔵庫は食べ物について知っている。カレンダーは時間について知っている。それぞれの人が自分の記憶を持つ。Context Grammarはこれを5種類のBrainとしてモデル化する。そして各Brainは同じ3層構造を持つ：Identity · Learning · Now。

01
Household Brain

共有記憶 — 家のルール、家族構成、共用資産、公共料金アカウント。

02
Person Brain ×5

一人ひとりの記憶 — 個人の好み、健康、人間関係、スケジュールのパターン。

03
Domain Brain ×N

ドメインごとの記憶 — Finance、Health、Work、Travel。ドメイン固有のルールと履歴を保持する。

04
Coordinator Brain

すべてのBrainを読む。衝突を解消する。Agentを指示する。指揮者であって、演奏者ではない。

05
Event Brain ×N

旅行、リノベーション、プロジェクトのための時限つき記憶。生まれ → 学習 → 統合 → 消滅。

Universal anatomy — すべてのBrainに共通の3層

Identity Layer — このBrainが何者か。更新周期：月〜年単位。  ·  Learning Layer — 繰り返しから蓄積されたパターン。更新周期：日〜週単位。  ·  Now Layer — 現在のToken値、有効なIntent、リアルタイムのコンテキスト。更新周期：秒〜分単位。

Floor 5 · AX Patterns

23のパターン、4つのグループ

Rule Engineが決定を出力したとき、UIのどこかが応答しなければならない。23のAX Patternは、その応答のための名前つき語彙 — デザインの意思決定をチームとサーフェスをまたいで再現可能・レビュー可能にする。

Group D
Delivery（配信）
D1–D6 · 6 patterns

システムがどのように出力を配信するか — 通知タイミング、サーフェスの選択、詳細度、割り込みしきい値。

Group E
Escalation（昇格）
E1–E5 · 5 patterns

サイレントな実行から完全な確認へいつ・どのようにエスカレーションするか — トラスト違反の回復、曖昧さの解消、オーバーライドフロー。

Group A
Autonomy（自律性）
A1–A8 · 8 patterns

Dial固有の動作 — 「Suggest」「Confirm」「Notify」「Auto」の各段階が、インターフェースではどう見えるか。4段階を名前と仕様で記述する。

Group X
Cross-cutting（横断）
X1–X4 · 4 patterns

グループを問わず適用されるパターン — マルチパーソン協調、グレースフルデグラデーション、セッション継続性、サーフェスのハンドオフ。

FAQ

よくある質問を整理する

Context Grammarはプロダクトなのか、フレームワークなのか、仕様書なのか？

デザイン言語だ。Material Designがコンポーネントライブラリではなくデザイン言語であるのと同じように。Context Grammarはコンセプトに名前をつけ、関係性を定義し、異なるプラットフォームで異なる方法で実装できるスキーマを提供する。特定のOSやAIプロバイダーに縛られていない。

通常のAI記憶システムと何が違うのか？

多くのAI記憶システムは、「あなたが誰か」と「今やったこと」の区別がないフラットなリストに事実を保存する。Context Grammarは三つのものを加える：構造化された層（Identity / Learning / Now）、1世帯あたりの複数のBrainタイプ（Person、Domain、Coordinator、Event）、そしてデザイン語彙 — Token、Dial、Pattern — によって、記憶がサーフェスとチームをまたいで一貫したインターフェース決定を駆動できるようにする。

2つのTrust Dialはなぜ8つのTokenとは別扱いなのか？

Autonomy DialはAIが何も聞かずにどこまで決定するかをコントロールする（4段階：Suggest → Confirm → Notify → Auto）。Disclosure DialはドメインごとにAIがアクセスできる個人情報の量をコントロールする。どちらもすべての決定を形成するライブシグナルとして8-Token数にカウントされる。しかし本質は関係設定であり、状況測定ではない。この区別はデザインにとって重要だ：他の6つのTokenは読み取り専用の観察、2つのDialはユーザーが所有するコントロールである。

これは投機的なデザインなのか、今日実装できるものなのか？

混在している。一部は今日出荷されている — Autonomy Dialのステージロジックはエージェントフレームワークの標準機能だ。Form FactorとSocial Exposure Tokenは簡単に読み取れる。他の部分は推論が必要だ — Cognitive Loadはカレンダーの密度と時刻のパターンから推定されるもので、直接測定はされない。Specsのページで各要素の現在の技術的成熟度を区別している。
