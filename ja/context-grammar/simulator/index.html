Context Grammar · 鮮明な10の瞬間

コンテキストを丸ごと読むと、
インターフェースはまったく変わる。

今日のアプリはどれも、ユーザーを見知らぬ人扱いする。銀行アプリは残高だけ隠せばいいのに、画面全体をぼかす。 音楽アプリは満員電車でもタップを求め続ける。カレンダーは来客中も子どもの歯科予約を表示したままだ。 以下の10の場面では、Physical State・社会的文脈・Intent・履歴を丸ごと読むAIが、 今日より明らかに良いインターフェースを生み出す。いずれも既存プロジェクトから設計済みのデザインだ。概念ではない。

01

電車が急に混んできた。

07:48 · 立ったまま · イヤホン装着 · ポッドキャスト再生中

コンテキスト対応AIなし

ポッドキャストの途中で車両が混んでくる。 操作できない。画面はつきっぱなしでバッテリーを消耗し、隣の人を眩しがらせる。 広告をスキップするには両手と足場が必要だが、それは今ない。

Context Grammarあり

端末がハンドオフを提案する: 「ウォッチ+イヤホン操作に切り替える?」 1タップでスマホはポケットの中へ。スキップ・巻き戻しはウォッチが担う。ポッドキャストは流れ続ける。

なぜこれが発動するか

  • Physical State 立ち · グリップ困難
  • Form Factor スマホ・ウォッチ・イヤホンすべて利用可能
  • Cognitive Load 低（受動的なリスニング）
  • Brain · Learning 通勤+ポッドキャストのパターン

適応とは縮小ではなく、適切なサーフェスに適切な役割を渡すこと。

02

カフェで銀行残高を開く — 隠すのはこの数字だけ。

14:12 · カフェのテーブル · 見知らぬ人が視線 · 銀行アプリ起動中

ぼかしの正解

コンテキスト対応AIなし

銀行アプリは反射的に画面全体をぼかすか（最近ありがちな対応）、後ろの人に残高が丸見えかのどちらかだ。 直前に使っていたAmazonカートやメモ、Spotifyも同じように過剰反応し、気にしていないものまで隠す。

Context Grammarあり

システムが隠すのはこのアプリの、この画面の、この場所での、この数字だけだ。 口座番号 ●●●● 4421。残高: タップで表示。取引ラベルは読める。 Spotifyに戻ればぼかしはなし — 文脈が判断する。パラノイアではない。

なぜこれがフレームワークの核心か

  • Social Exposure 公共 + 見知らぬ顔
  • Disclosure Dial 最小（銀行ドメインのみ）
  • Domain 銀行 — センシティブさはフィールド単位
  • Brain · Identity 「残高はプライベート。取引名称は違う」

「公共→ぼかす」は粗すぎる。フレームワークが読むのはこのアプリ、このフィールド、この相手だ。

03

来客が玄関のベルを鳴らした。

19:02 · 玄関 · スマートスクリーンに家族カレンダー表示中

コンテキスト対応AIなし

廊下のディスプレイはいつも通りの表示だ: 明日のソウタの歯科予約、 ハナのお迎え時間、銀行のリマインダー、宅配の到着予定。スリッパを探している間、配管工が全部見る。

Context Grammarあり

ドアベル+未登録の顔 → 画面がゲスト表示に切り替わる。予定もなし、名前もなし、用事もなし。 Wi-Fiパスワード、スリッパの案内、「すぐ戻ります」のメッセージのみ。玄関が閉まれば家族カレンダーが戻る。

なぜこれが発動するか

  • Social Exposure trusted_partner → social_acquaintances（1人の顔で変わる）
  • Disclosure Dial 家族ドメインは「存在のみ」に制限
  • Brain · Identity 「来客は家族のスケジュールを見ない」
  • Form Factor 玄関ディスプレイ、一目で読める

サーフェスが覚えるのは誰が読んでいるか。どこにあるかだけではない。

04

家族で夕食を決める — 価格は表示する。

18:30 · リビング · TVキャスト中 · 家族全員がソファに

Intentのテスト

コンテキスト対応AIなし

単純なプライバシーシステムが「子連れ+TV」を検知して価格をぼかす。 子どもたちは何を選ぼうとしているのかわからない。 会話がぎこちなくなる: 「真ん中のやつ」、「チキンのやつ」。

Context Grammarあり

ハナのスマホ · リモコン

¥1,820 サーモンポケ · 25分
↑ ← OK → ↓

TVには価格つきの3候補がそのまま表示される — それが家族の会話だ。 ハナのスマホはDパッドリモコンになる: OKボタン1つ、スクロールなし、入力なし。 同じ部屋でも1時間後に誕生日プレゼントを見ていれば、ぼかす。

なぜここでは価格をぼかさないか

  • Social Exposure family_with_children
  • Intent joint_decision（決定的なシグナル）
  • Disclosure Dial フル · 家庭食事ドメイン
  • Brain · Learning 「この家族はここで47回価格を表示してきた」

フレームワークが読むのはIntentだ。同じTokens、違うIntent、逆のUI。

05

夕食時、中目黒を歩いている。

19:15 · 自宅から2km · このエリアでInstagramに12件保存済み

コンテキスト対応AIなし

Mapsが「中目黒のおすすめレストラン」を一般リストで出す。3ヶ月前にInstagramで丁寧に保存した店は1つも出てこない。 あのブックマークは別のアプリに閉じ込められたまま、今の居場所も時間も関係ない。

Context Grammarあり

3/12に保存 · 営業中
Higashiya
8/4に保存 · 営業中
Cafe Facon
先週保存 · 営業中
保存済み3件 · 今すぐ営業中 · 徒歩8分以内

そのエリアに入ると、マップが静かに今開いている保存済み3件を浮かび上がらせる。 徒歩圏内に絞り込み済み。3ヶ月前に保存したブックマークが、初めて役に立つ瞬間だ。

なぜこれが発動するか

  • Physical State 徒歩 · 19:15 · このエリア
  • Brain · Learning このエリアのInstagram保存12件
  • Feasibility 今営業中 + 徒歩8分以内
  • Priority Weight 低 — アンビエント、割り込まない

ブックマークはアプリの中で死ぬ。コンテキストが浮かび上がらせるとき、生きる。

06

手が汚れている、レシピは途中。

19:42 · キッチン · タイマー作動中 · 子ども2人が叫んでいる

コンテキスト対応AIなし

ターメリックで汚れた指の関節でレシピをスクロールする。交差汚染を避けながら。 最も必要なときにスマホの画面が消える。Siriに叫ぶと「混ぜる」が「閉める」に聞こえる。

Context Grammarあり

スマホが冷蔵庫のディスプレイにレシピを渡す — 大きく、一目で読め、音声優先。 「次へ」は声で。タイマーはキッチンのどこからでも見える。 スマホはカウンターの上で沈黙する。システムが隠しているのではない、移動させている。

なぜこれが発動するか

  • Physical State 両手がふさがっている · 騒音あり
  • Form Factor スマホ + 冷蔵庫どちらも利用可能
  • Cognitive Load 中程度 · 複数の要求が同時進行
  • Brain · Learning 「火曜の料理パターン」

その瞬間に最適なデバイスは、手に持っていないものだ。

07

映画がベッドに続く。

22:38 · TV一時停止 · 寝室でスマホをアンロック

コンテキスト対応AIなし

TVが止まる。寝室に移動する。ストリーミングアプリを開く。タイトルを検索する。正しいエピソードを選ぶ。 止めた場所に再生位置をドラッグする。5ステップ、どれも視聴ではない。

Context Grammarあり

寝室でスマホをアンロックすると、カードが1枚だけ最上部にある — 「Past Lives · 47:12 から再生」。タップすれば始まる。 さっきまでリモコンだったスマホが、今度はスクリーンになる。 ハンドオフは頼む前に起きていた。

なぜこれが発動するか

  • Form Factor 変化 · TV → 寝室のスマホ
  • Brain · Now アクティブタスク = 47:12の映画
  • Physical State lying_down
  • Priority Weight 低 · 夜のリラックス

継続性はボタンではない。コンテキストを読んだときのデフォルトだ。

08

深夜の帰宅ドライブ — わずかにフラつく。

23:14 · 高速道路 · CarPlay · 45分走行 · 残り30分

コンテキスト対応AIなし

MapsがETAを知らせる。音楽は流れ続ける。InstagramのDMで通知音が鳴るかもしれない。 遅くなった反応、ステアリングの修正、深夜という時間帯 — 何も読まれない。たぶん帰れる。

Context Grammarあり

音声のみ、1行: 「4分先にコーヒー休憩あり、迂回90秒。使いますか?」 1語で答えられる。車線変更してマップを読む必要なし。通知もDM音もなし — 駐車するまで待つ。

なぜこれが発動するか

  • Physical State 運転 + 深夜 + ステアリング修正
  • Cognitive Load 高 → Brain が疲労を推測
  • Priority Weight 安全最優先
  • Feasibility ルート上でコーヒー休憩が取れる

状況が大きくなるほど、インターフェースは小さくなる。

09

電気を消す — スマホも待つことに同意する。

23:50 · 就寝中 · 最後のスクロール · 充電中

コンテキスト対応AIなし

通知が届き続ける。23:52にSlack。00:14に配達確認。02:31に「サブスクが更新されます」。 スマホがベッドサイドで光り続け、まだ存在しない未来の自分のために同期する。

Context Grammarあり

00:42

水曜日 5月7日

◐

通知14件を保留中。

重要のみ通過 · 学校 · 家族

14件の通知をバッファし、06:30に1つのサマリーで届ける。 学校と家族は常時オン — フレームワークは何が起こしていい理由かを知っている。 タップ前からスクリーンはウォームトーンで暗くなっている。

なぜこれが発動するか

  • Physical State 横になる · 充電中 · 自宅
  • Cognitive Load 低 · クールダウン中
  • Priority Weight 標準は「明日」に格下げ
  • Brain · Identity 「学校+家族は常に割り込む」

抑制は機能だ。フレームワークは通知しないことを選ぶ。

10

帰宅5分前、家も動き始める。

18:32 · 車 · 最後の道 · トランクに食材

コンテキスト対応AIなし

帰宅する。家は暗い。冷蔵庫は9時間前と同じ冷蔵庫のままだ。何も来ることを知らなかった。 鍵を探して、電気をつけて、ゼロから夕食を考える。

Context Grammarあり

ジオフェンス + Brain の履歴がゆっくりとした起動を引き起こす。 廊下の照明が事前に温まる。冷蔵庫は今夜の夕食候補を、実際に中にあるものと今買ってきたものから提案する。 家族カレンダーに「アオイ 19:30までサッカー」 — 静かな夕食ができる。

なぜこれが発動するか

  • Physical State 運転 · 自宅に接近中
  • Brain · Identity 家庭のルーティン · 18:30 = 夕食準備
  • Feasibility 食材のクロスチェック済み
  • Form Factor アンビエントサーフェスがユーザーより先に起動

家は舞台ではなく、参加者だ。

いま見たもの

10の場面。10通りの正解。1つのフレームワーク。

共通点に気づいただろうか — そして違いにも。 同じ手法は1度も使っていない。同じデフォルトにも頼っていない。 それぞれがこの状況、この人、このIntentを読んで、 その状況にふさわしいインターフェースを生み出した。それがContext Grammarだ。
