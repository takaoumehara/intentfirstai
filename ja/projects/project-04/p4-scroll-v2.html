Enterprise Context Brain

5つのBrain。
ひとつの会社の記憶。

Org Brainは会社そのものについての真実を持つ—組織図、ポリシー、用語集、歴史。Brand Brainはブランドごとの判断DNA（B2C用とB2B用、2つ並列で動く）。Research Brainはユーザー理解。リアルタイムのデータが流れ込み続ける。Project Master Brainは戦略を考える脳—他の3つと過去のプロジェクト履歴を読み、何を始めるか・止めるか・殺すかを決める。Project Brainは時限付き—キックオフで生まれ、終了時に死に、学びだけ残す。

どのBrainの中にも、同じ3層の解剖学：Identity · Learning · Now。Identityは変わらないもの。Learningは蓄積されるもの。Nowは流れているもの。レイヤーは記憶の普遍単位。Brainは認知の単位。

Concept · Brain architecture 土台にOrg Brain。その上に Brand Brain（ブランドごと）と Research Brain。Project Master Brain がすべてを読み、時限付きの Project Brain を生む—どれも同じ3層の解剖学（Identity · Learning · Now）を持つ。

Brain 01 · Org Brain

会社が、会社自身について
知っていること。

すべての土台になる Brain。Org Brain は会社の構造的な事実を抱える—誰が誰の部下か、ポリシーは何か、社内用語の辞書、会社がここまでたどり着いた歴史。ゆっくり変わる、全社員のもの、永続的。

何年分ものリサーチが、
ようやく使える。

Research チームは何年も調査を回してきた。年に10〜15本—エスノ、サーベイ、インタビュー連発、A/B テスト。どれも FINAL_v3.pdf として Drive のフォルダに着地し、開く人は4人ぐらい。プロジェクトが立ち上がるとき、誰かが直近の1本にざっと目を通す。3週間後にはキックオフブリーフがリサーチを上書きしている。仕事はやった。誰も使えなかった。

Research Brain は、他のすべてのブレインと同じ 3 層構造をそのまま持つ。古い PDF とライブデータが同じバケツに放り込まれているのではなく、別の層に住んでいる—この区別は問い合わせ時に効いてくる。

Learning

止まらないライブデータ

Priya の使い方は、こう。新しいプロジェクトを起こすとき、彼女は Research Brain にプロジェクトの context をブリーフする—ゴール、対象セグメント、未解決の問い。Research Brain は 3 層すべてを横断して読む—Identity から手法、Learning から過去のリサーチ、Now から今日のデータ—このプロジェクトに関連する断片を選び、新しい Project Brain の Learning Layer に書き込む。続く6週間、チームは Drive を検索しない—自分たちの Project Brain を問う。それは 2024年のセグメンテーション調査が何を見つけたかも、今朝 NPS が下がったことも、すでに知っている。

Brain 04 · Project Master Brain

どのプロジェクトを
始めるかを、決めるBrain。

3つのBrainは知識を蓄える。Project Master Brain（PMB）は違う—その知識で考える。PMB は Research のシグナル、Brand の判断制約、Org のキャパシティを読む。会社が走らせた・失敗した・殺した・保留した・始めなかったプロジェクトをすべて記憶している。Research のシグナルが届くと、PMB は審議の場になる：これはプロジェクトになるか？どのプロジェクトに？コストはいくらか？

PMB は、Priya が自分のポートフォリオと会話する場でもある。月曜の朝、スタンドアップの前に、彼女は PMB ダッシュボードを開く。走行中4。保留2。金曜にシグナルが1つ届いた。PMB はもう、それにどう対応するかの草案を書いている。決定するのは Priya だ。

Identity Layer
ポートフォリオ戦略
この会社が何をやるかを決めるルール

「B2C のアクティブは4プロジェクトまで」「kill 基準：中間で ROI が 2× 未満」「B2C : B2B = 60 : 40 のデザイン・キャパ配分」。月単位では変わらない判断ルール。

Learning Layer
パターン銀行
過去のすべてのプロジェクトから蒸留

「価格テストは70%失敗する」「リブランドは6ヶ月ではなく9ヶ月かかる」「保留プロジェクトの15%が復活する」。プロジェクトより長く生き残る教訓。

Now Layer
LIVE
今のポートフォリオ
走行・保留・提案・新着シグナル

走行中の Project Brain への参照。プロジェクトごとの状態。Research から届いたばかりのシグナル。Priya 待ちの提案。死んだプロジェクトはここに住まない—Learning の教訓と、Archive のファイルに変わる。

Backstage · PMB はどう考えるか
Research シグナルが届くと、PMB は過去のパターンと突き合わせ（「この種類は3回見た—結果は A、B、C」）、Brand Brain の制約を確認し（「シンプルさ、コンバージョン目当てのテクニックは禁止」）、Org Brain のキャパシティを読み（「Maya 60%、Dev 80%」）、提案の草案を浮かび上がらせる。PMB は自動的にプロジェクトを生まない。決定は Priya のもの—でも、それは「決定」であって「勘」ではない。

Brain 05 · Project Brain

3層構造、
時限付き。

各 Project Brain も、システム内の他のすべてのブレインと同じ 3 層構造を持つ。Identity はプロジェクトの意図・成功条件・未解決の問い。Learning はチームが試したこと・決めたこと・捨てたことの蓄積。Now は今このスプリントのライブな状態。プロジェクトが閉じるとき、3 つの層は別々の運命をたどる—Identity はアーカイブへ、Learning は Org Brain へ卒業、Now は蒸発する。

Identity Layer

artifact_vecs  = [embed(a) for a in sprint.shipping_artifacts]   # figma, copy, commits

fidelity_now   = mean(cosine(intent_vec, a) for a in artifact_vecs)
fidelity_prev  = brain.read("atlas.intent_fidelity@last_sprint")
delta          = fidelity_now - fidelity_prev

# trace the drop to the meeting that caused it
trigger        = meeting_brain.find_decision(
                   correlated_with = artifact_diff(prev, now),
                   within          = "7 days"
                 )

# surface a question, never a verdict
if fidelity_now < 0.70 and delta < -0.10:
    surface_to(role="product_owner", surface="iphone", body={
      "score":      fidelity_now,
      "drift_from": identity_layer.intent_summary,
      "drift_to":   describe_artifacts(now),
      "trigger":    trigger.summary,
      "question":   "Accept the drift, or update the Intent?"
    })
else:
    pass  # silent — no notification

どう作ったか · 残した決定、捨てた決定

仕上げの裏にある思考。

シニアのポートフォリオは、出力だけでなく、思考を示す。判断が自明でなかった6つの決定—3つ残し、3つ捨てた。

決定01 · 残した 1ダイヤルではなく、5役割×5領域
全社共通のAutonomy Dialではなく、Stakeholder Autonomy Matrix。
最初は単一ダイヤル版を試した—「チーム全体がProject Master BrainをNotifyレベルで信頼」。3つの会議で破綻した。MayaはUIにAutoを欲しがり、LeenaはブランドにVetoが必要だった。同じ数字でも、結果が真逆。役割×領域のマトリクスにした。信頼は一個の数字ではない。関係ごとの姿勢だ。
決定02 · 捨てた 「生産性スコア」
個人ごとの生産性スコアを、プロトタイプレビュー1回で殺した。
「Priya · 今スプリントの生産性87%」—Brainとのやりとりすべてが監視に変わった。プロジェクトレベルのIntent Matchに置き換え—測るのは仕事であって、働く人ではない。同じシグナル、不安なし、マネージャー・ダッシュボードなし。
決定03 · 残した Project Master Brainは問いをひとつ渡す
Fidelityが下がったら、Project Master Brainは問いをひとつ浮かべる—判決は下さない。
初期版はIntent Matchが閾値を下回るとスプリントを自動で止めた。パートナーではなく、ブレーカーのように感じた。問いひとつに置き換えた：「ドリフトを受け入れるか、Intentを更新するか？」判断はPriyaに残る。Project Master Brainに残るのはトレースだ。
決定04 · 捨てた ツールごとのプラグイン
Slackボット、Jiraプラグイン、Figmaプラグインを、プロダクトとしては捨てた。
5つのプラグインUIをデザインすると、同じ3つのアフォーダンスを5回重複させた。3つの動詞（Read / Write / Subscribe）を持つひとつのBrain APIにまとめた。どのツールも同じ契約を呼ぶ。プラグインはAPIであって、UIではない。
決定05 · 残した Project Brainは卒業する
Now Layerは蒸発する。Learning LayerはOrg Brainへ溶ける。Identity Layerはアーカイブへ圧縮される。
すべてを永久に残すのも試した—検索が腐り、シグナルが減衰し、どのクエリも時間がかかった。すべて消すのも試した—次のプロジェクトはゼロから再導出した。3段階の卒業が、大事なシグナルだけを残し、ノイズは見送った。
決定06 · 捨てた 「チャットボットとしてのBrain」
「Project Master Brainと会話する」というヒーロー・アフォーダンスを捨てた。
どのサーフェスからもチャットボックスを引き抜いた。Project Master Brainは話しかける相手ではない—サーフェスたちが話しかけるメモリ層だ。読むのはFigmaの中、Slackの中、iPhoneのブランドチェック画面、AirPodsで起きる。チャットボックスがあれば、アーキテクチャを間違った形に平らにしただろう。

今夜持ち帰れる3つ

移植可能な原則。

Project Master Brainを取り除いてみる。意図が、それを抱える人より長く生き残らなければならないチームすべてに当てはまる、このケースの3つのパターン。

原則01
記憶には速度がある。3つともデザインせよ。
Identity（遅い—意図、ミッション、判断のDNA）。Learning（中間—決定、トレードオフ、パターン）。Now（速い—今このスプリントのブロッカー）。書き込みルールも、レビューのアフォーダンスも、アーカイブでの運命も、それぞれ違う。ひとつのチャット履歴に放り込むな。
原則02
信頼は役割×領域。ひとつのダイヤルではない。
単一のAutonomy Dialは、姿勢を平らにしてしまう。MayaはUIディテールにAutoを欲しがり、LeenaはブランドにVetoが必要だ。スライダーでなく、マトリクスを作れ。Suggest → Confirm → Notify → Auto を、役割×領域ごとに当てる。
原則03
決定は、下された瞬間にデータになる。
スタンドアップの文字起こしが3日後にメモになるなら、制約は失われている。決定と、それが天秤にかけた制約を、その場で、問えるレイヤーへ捕まえる。メモはない。Brainがメモだ。
